## 2. 会话「团队视图」九栏 ↔ 面板方法

| 栏 | 读的方法 | 写入口 | 备注 |
|---|---|---|---|
| 概览 | `status` + `overview` | — | 计数、项目 seq / graphRevision / configRevision |
| 任务 | `board`（+`overview` 取团队名） | `taskCreate`（新任务） | 点卡片进任务详情（`task`） |
| 团队 | `overview` | `teamDisband` / `captainTakeover`（两段确认） | 名册、队长会话与 generation |
| 流程 | `runs` | — | WorkflowRun 列表 |
| 定义 | `definitions` | `definitionPublish`（令牌） | 项目定义副本 |
| 知识 | `knowledge` | — | 提案与采纳走 agent 工具 |
| 记忆 | `memory` | `memoryRemember` / `memoryForget` | SQLite bank |
| 审计 | `audit`（limit 200） | — | 与账本事件数对账（25 记录里有三例） |
| 设置 | `settings` | — | 只读配置投影 |

任务详情（不在九栏里）：`task`；门禁裁决表单只在 `review` 状态出现，写 `gateVerdict`。

## 5. agent 工具：队长 15 · 成员 3

- 队长：`myteam_read_board` / `read_task` / `read_team`、`preview_disband` / `preview_takeover`、
  `create_team` / `create_task`、`start_workflow` / `create_workflow`、`appoint_member`、
  `claim_task` / `review_task` / `complete_task`、`propose_knowledge` / `adopt_knowledge`。
- 成员：`myteam_progress` / `myteam_evidence` / `myteam_submit_review`。
- 身份只来自会话绑定（`application/actor-resolution.ts`）；参数里的 `teamId` / `memberId` 一律不可信；
  两个 preset 不共享注册表。

> 计数口径：**以前文档里写的「成员 13 个」是错的**（那是成员 preset 早期规划的数目）。
> 现行以生成契约 `docs/contracts/tool-surface.md` 为准：队长 15 + 成员 3。

## 6. 三个「接口有、屏没有」的方法：已接入（2026-11-23）

| 方法 | 现在的入口 | 测试 |
|---|---|---|
| `run` | 流程栏点运行行 → 运行详情（完成规则、templateKey → task 映射、各任务状态、返回按钮） | t39「流程栏：运行行能点开详情」 |
| `effects` | 流程栏下方「副作用」区块：三态 + failed/cancelled/outcome-unknown 计数与清单 | 同上（断言 effects 请求与计数渲染） |
| `migration` | 设置栏底部「v1 迁移影响面」（原来 `tab==='migration'` 是**没有入口的死分支**，已删除） | t39「设置栏：底部带 v1 迁移影响面」 |

九栏的标签与顺序没变（没为了塞入口加第十栏）：两个新入口都挂在已有栏里，符合设计稿的
导航纪律。`run` 详情在狗粮项目里点不到（该项目 0 个 Run），由单测覆盖；`effects` 与 `migration`
在隔离实例里真机截图核对过（0 条副作用、迁移被 `UNKNOWN_LAYOUT` 拦下，都如实显示）。
剩余与设计稿的差距仍是 R-3（依赖图 / 泳道 / 审批队列 / 归档 四屏），那是**新屏**，不是挂入口。
