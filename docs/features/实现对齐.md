| `globalUnpublish` | 令牌（两步） | ✅ 全局库详情页「下架这份定义」（只从目录隐藏，文件保留、引用方仍可读） | t58 / t39 |
| `projectDestroy` | 令牌（两步 + 输项目名） | ✅ 设置栏「删除项目数据」（不可撤销；先看逐项影响面与总字节数，输对项目名才能确认） | t59 / t39 |
| `definitionSave` | 直接确认 | ✅ 定义栏展开角色后的「保存定义」（只改 profile 文本，能力集原样带回） | t52 / t39 |
| `memoryRemember` | 直接确认 | ✅ 记忆栏「记一条」 | t41 / t39 |
| `memoryForget` | 直接确认（软删留痕；`彻底删除` 才带 `hard`） | ✅ 记忆栏每行「遗忘」/「彻底删除」 | t41 / t39 |

几个刻意的取舍，写在这里免得被当成漏做：

- **`taskMove` 不开「认领」**：认领要 `memberId`，而认领是成员自己的事（成员会话走 `myteam_claim_task`）。
  面板只开人类方向：取消 / 重开。`done` 也不给按钮——完成必须走门禁裁决。
- **`memoryForget` 的团队归属从 `bankId` 解析**（`team:<id>` / `team:<id>:member:<mid>`），
  解析不出来就拒绝并说明，绝不猜一个 teamId。
- **`definitionSave` 只编辑项目副本的角色 profile**：工作流的 `templates` 是结构化图，
  面板不做图编辑器：队形用行式文本（`key | 角色 | 数量 | 父槽位`），校验全在域里。
蓝图现在能建也能改，项目副本这一侧已有界面（定义栏，t39 三条守着；能力见 t53）。
`g-*-edit` 那三页是**全局库**编辑，
  `definitionSave` 管不到，仍属未做。

> 现在 12 个都有 UI，t39 从 23 条涨到 35 条，新增的 12 条专门守这些写路径
> （含「点一次只发一次写请求」和「能力集原样带回」）。
