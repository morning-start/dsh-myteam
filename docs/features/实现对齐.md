## 2. 会话「团队视图」九栏 ↔ 面板方法

| 栏 | 读的方法 | 写入口 | 备注 |
|---|---|---|---|

| 任务 | `board`（+`overview` 取团队名） | `taskCreate`（新任务） | 点卡片进任务详情（`task`） |
| 团队 | `overview` | `teamDisband` / `captainTakeover`（两段确认） | 名册、队长会话与 generation |
| 流程 | `runs` | — | WorkflowRun 列表 |
| 定义 | `definitions` | `definitionPublish`（令牌） | 项目定义副本 |

| 记忆 | `memory` | `memoryRemember` / `memoryForget` | SQLite bank |
| 审计 | `audit`（limit 200） | — | 与账本事件数对账（25 记录里有三例） |
| 设置 | `settings` | — | 只读配置投影 |

任务详情（不在九栏里）：`task`；门禁裁决表单只在 `review` 状态出现，写 `gateVerdict`。

**待你确认**（也不在九栏里）：从概览横幅的「逐项确认」进独立一整页，读 `pendingApprovals`。
设计稿 `p-approval` 分四类，**现在四类都接通了**（2026-11-24 收口）：

| 设计稿要的 | 现状 |
|---|---|
| 门禁裁决 | ✅ 任务停在 `review` 且当前 Attempt **没有裁决**时列入；下过裁决的进「已处理」 |
| 全局发布 | ✅ `definition.publication.requested` 落了但还没 `outcome` 的列入 |
| 计划批准 | ✅ **已接通（P1–P6）**：`TeamPlan` 是独立聚合，`team.plan.proposed` 只落计划、**不建任何实体**；批准（`plan.approve`，人类专属 + 令牌绑 `planHash`）在**一个原子批次**里建出团队 / 配置 / 成员 / Run。见 [决策：团队计划批准](../decisions/团队计划批准.md) |
| 队长接管 | ✅ **已接通（2026-11-24）**：`myteam_propose_handoff` / `proposeCaptainHandoffCommand` 落 `captain.handoff.proposed`，投影记 `pendingHandoffs`，待确认里列出来；人类确认（`captain.handoff.confirm` + 令牌）才 generation +1。提案本身**不改队长** |

计划卡的两个动作：**批准并开跑**（令牌两段式，令牌绑 `planHash`）、**丢弃**（direct，零回滚）。
**不做「改计划」**：设计稿没给「编辑已提交计划」的入口，改法只能是丢弃后重新提案。

`unsupported.planApproval` 与 `unsupported.captainTakeover` 现在都是 `false`；
界面上那段「哪类画不出来」的说明已经消失，t39 有断言**锁住它不许回来**。

几个刻意的取舍，写在这里免得被当成漏做：

- **`taskMove` 不开「认领」**：认领要 `memberId`，而认领是成员自己的事（成员会话走 `myteam_claim_task`）。
  面板只开人类方向：取消 / 重开。`done` 也不给按钮——完成必须走门禁裁决。
- **`memoryForget` 的团队归属从 `bankId` 解析**（`team:<id>` / `team:<id>:member:<mid>`），
  解析不出来就拒绝并说明，绝不猜一个 teamId。
- **`definitionSave` 只编辑项目副本的角色 profile**：工作流的 `templates` 是结构化图，
  面板不做图编辑器：队形用行式文本（`key | 角色 | 数量 | 父槽位`），校验全在域里。
蓝图现在能建也能改，项目副本这一侧已有界面（定义栏，t39 三条守着；能力见 t53）。
`g-*-edit` 那三页是**全局库**编辑，
  `definitionSave` 管不到，仍属未做。

> 现在 12 个都有 UI，t39 从 23 条涨到 35 条，新增的 12 条专门守这些写路径

### 与上一版（2026-11-24）的差异

上一版写着「30 页有实现、9 页没有」，其中三条已经过期：

- **I 组全局库编辑**标 ❌ —— 实际 `globalDefinitionSave` / `globalUnpublish` 都已接通；

### 一处如实标注的缺口

`p-archive` 的「花费」块（token 用量 / 调用次数 / 命中率）**画不出来**：
项目里没有 token 计量数据源，事件账本只记业务事实。界面上写「未采集」并说明原因，
不画估算数字。要补这一块，得先有计量数据源，属于新能力而不是补屏。
