# 用户场景与功能（现行）

> 用途：给面板、工具与迁移功能提供**需求来源**。旧文档
> `historical/12-用户场景与功能设计.md` 描述的是 v1 行为；本页只写 v2 已实现或
> 已设计的能力，并标明「未实现」。

## 角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 人类（用户） | 建团队、批准发布、批准计划、接管队长、解散团队、执行 cutover、硬删除记忆 | 代替成员提交执行事实 |
| 队长（Captain） | 建任务/工作流、聘任成员、认领与裁决、写团队记忆、读本团队全部记忆 | 解散团队、发布到全局库、硬删除记忆 |
| 成员（Member） | 提交进度/证据、提交评审、写自己的私有记忆 | 建任务、改定义、完成自己任务、读他人私有记忆 |
| 面板 | 只读查询（status/overview/board/task/team/definitions/migration） | 任何写操作 |

身份只来自会话绑定；参数里的 `teamId`/`memberId` 不可信。

## 功能边界（刻意的「不做」）

- 不做全自动记忆：知识必须先提案、再由队长或人类采纳；
- 不做自动重试：门禁失败、确认令牌过期都由人或上层重新发起；
- 不做跨团队读记忆：`team:<id>` 严格隔离；
- 不做「迁移时补历史」：没有证据的旧事实宁可不迁移，也不伪造 Attempt。
