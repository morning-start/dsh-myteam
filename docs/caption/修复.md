## 4. 领域缺陷：`nextAttemptGeneration` 会复用已用过的 generation
- Saw: §P 提案记了一条「`claimTaskCommand` 的 Attempt generation」，但没核实。逐行读发现：
  `commands.ts:36` **导入了** `nextAttemptGeneration`，却**从未调用**（全文件只有 import 那一行）——
  死导入；`claimTaskCommand:934-935` 自己 `reduce` 了一遍。两份实现，语义不同：
  - 领域层 `nextAttemptGeneration(previous: Attempt | null)` → `previous === null ? 1 : previous.generation + 1`
  - 应用层 → `max(该任务全部历史 attempt.generation) + 1`
- Decided: 先证明差异真能发生，再决定改哪边。任务被 cancel / 会话丢失后回到 ready 时
  `task.attemptId` 变回 `null`，但历史 attempt 仍在账本里 —— 领域层这时返回 1，**复用了
  已经用过的 generation**，与它自己的注释「严格递增，不允许复用旧值」直接矛盾，也让
  `assertCurrentAttempt` 的「状态 + generation 一起核对」失去意义（迟到的旧写入会和新 attempt 撞号）。
  应用层是对的，领域层是错的 —— 而且领域层才是被测试覆盖、被文档引用为「口径」的那一份。
- Did:
  - `plugin/src/domain/tasks/task.ts` —— 签名改为 `nextAttemptGeneration(history: readonly Attempt[])`，
    取最大值 + 1；注释写明为什么参数是「全部历史」而不是「当前 attempt」。
  - `plugin/src/application/commands.ts` —— `claimTaskCommand` 改调领域函数，删掉自己那份 reduce。
  - `plugin/test/t04-domain-task-config.test.ts` —— 补三个断言：空数组→1、历史 1/2/3→4（回归锁）、
    乱序取最大值。原用例只覆盖「有 previous」分支，漏的正是出问题的那个分支。
- Evidence:
  - 探针 `node tmp/probe-generation.mjs` → `历史 generation: 1, 2, 3` /
    `领域层 nextAttemptGeneration(null) => 1` / `应用层 max(历史)+1 => 4` /
    `不一致：领域层复用了 generation=1，而它已被 attempt_1 使用`，exit 1
  - 修复后 `node --test test/t04-domain-task-config.test.ts` → `pass 12 / fail 0`，exit 0
  - **守卫反证**：把实现改成 `history[history.length-1]!.generation + 1`（只看最后一条）→
    `✖ Attempt generation 单调递增`，`pass 11 / fail 1`，exit 1；恢复 → `pass 12 / fail 0`
  - `node --test --test-reporter=tap test/*.test.ts` → `tests 348 / pass 348 / fail 0`
  - `node tools/check-all.mjs` → `✓ 全部 9 项门禁通过`，exit 0
  - `node tools/verify.mjs` → `VERIFY_OK`，exit 0
- Outcome: done —— 这是本轮唯一的行为变化，且是**收紧**：generation 现在真的严格递增。

### 死路（记下来，别重踩）
- **`check-all` 的架构门禁断言写的是失败分支**：`check-architecture.mjs` 通过时打印 `ARCH_OK ... violations=0`，
  失败时才打印 `ARCH_VIOLATIONS ...`。断言后者等于「门禁通过反而判缺行」。这条门禁自 CHG-209 起从未绿过。
- **`find-dead-exports` 的转义被改坏过多次**：`\s`/`\w`/`\b` 在传递中被存成「反斜杠 + 字母」，
  导致导出名提取正则永远匹配不上（`names` 为空 → 门禁假绿）。修法：全部转义由
  `String.fromCharCode(92)` 拼出，文件里一个反斜杠字面量都不写。
- **`npm ci` 在本仓库不可能成功**：没有 `package-lock.json`，且测试用的宿主协议包在
  `plugin/node_modules`（不入库）。CI 里删掉安装步骤，不是改成 `npm install`。
- **`nextAttemptGeneration` 的旧签名掩盖了缺陷**：收「当前 attempt」时，任务回到 ready
  （`attemptId === null`）就返回 1。原测试只覆盖「有 previous」分支，正好漏掉出问题的那个。
- **`npm install --no-save` 每次会重算整棵树**：分两次装 `typescript` 与 `@types/node`，
  第二次会把第一个删掉（实测）。必须**同一条命令**装两个包。
- **JS 块注释里的 `**/*` 会提前闭合**：`lib/**/*.mjs` 中的 `*/` 结束了注释，整个文件变语法错误。
  宿主报 `failed to import: SyntaxError: Unexpected token '*'`，插件整体不装载，而所有离线门禁全绿。
- **`verify-live` 首次启动不预置 workspace.json 就会写进用户真实目录**：旧逻辑只在文件已存在时
  打补丁，首次启动时宿主自建一个指向 `Documents\deepseek-harness\default-workspace` 的条目。
- **`cloneJson<T>` 保留原类型**：它不能把 interface 转成 `JsonValue`。要转必须显式
  `JSON.parse(JSON.stringify(x)) as JsonValue`。
- **`as const` 元组的 `.includes()` 参数被收窄成字面量联合**：传 `string` 会被 tsc 拒。
  修法是包一层 `readonly string[]` 参数的辅助函数。
