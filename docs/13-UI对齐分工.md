## 一、口径

1. **设计稿是唯一权威**：不自行发明版式。每屏动手前先读对应 `design/*.html`，再从 `design/app.css` 抄规则名与度量。
2. **样式纪律**（`t13c-3` 硬断言，违反即红）：
   - 只用 `--dsw-alias-*` token；
   - **禁写十六进制颜色**（`#fff` 也不行，用 `--dsw-alias-*` 或 `color-mix(in srgb, var(--dsw-alias-*) N%, transparent)`）；
   - **禁写 `font-family`**（宿主统一字体栈）。
3. **不新增依赖、不改加载机制**：仍是 `window.__ModuleLoader__.load` 单文件形态。
4. **数据只从 `getBoard` / `getRoles` / `getTokens` / `getAudit` / `getConfig` 派生**（design-notes §八-1），前端不造第二事实源。
5. **H4 三通道**：状态一律「文字 + 图标 + 形状」，颜色只作第三顺位。

## 三、并发写协议（同一文件 6 人并行）

1. **只改自己区域**：用 `edit` 做字面替换，锚点必须在自己区域内且唯一；跨区域需求先告诉 Lead。
2. **少而大**：优先「一次插入一整块 CSS」「一次替换整个组件体」，不要几十次小编辑。
3. **遇到 `FS_STALE_VERSION`**：重新 `read` 该段 → 把改动压到最新内容上 → 重试。**不要**用脚本 `write` 整个文件（会覆盖别人的改动）。
4. **禁止**跑 `prettier` / 批量重写脚本 / 修改行尾。
5. 每轮结束跑：`node --check plugin/client/client.js`。
6. 测试文件**各自新建**，不共用：`plugin/test/t61-design-g1.test.ts` … `t66-design-g6.test.ts`。
