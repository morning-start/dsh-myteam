# 能力矩阵（现行）

> 取代 `historical/19-资源模型与能力矩阵.md`。数字来自代码：动作集合见
> `src/domain/permissions/policy.ts`，工具面见 `src/application/tool-specs.ts`
> 与 `docs/contracts/tool-surface.md`。

## 1. 身份 × 动作

| 动作族 | 人类 | 队长 | 成员 | 系统 |
|---|---|---|---|---|
| 读项目 / 定义 / 配置 | ✅ | ✅ | ✅（只读） | — |
| 建/改定义、发布到全局 | ✅ | ✅（请求发布） | ❌ | ❌ |
| 建/改/归档团队 | ✅ | ✅ | ❌ | ❌ |
| 指定/接管队长 | ✅（确认令牌） | 提议 | ❌ | ❌ |
| 聘任/释放/暂停成员 | ✅ | ✅ | ❌ | ❌ |
| 建/改/取消任务、改依赖 | ✅ | ✅ | ❌ | ❌ |
| 认领任务 | ✅ | ✅ | ✅（自己） | ❌ |
| 写进度 / 证据 / 提交评审 | ✅ | ❌（不代替成员） | ✅（自己） | ❌ |
| 裁决 / 完成 / 重开 | ✅ | ✅ | 仅在提交评审时交叉检查 | ❌ |
| 知识提案 / 采纳 / 归档 | ✅ | ✅ | 提案 | ❌ |
| 写配置 / rebase | ✅ | ✅ | ❌ | ❌ |
| 读写记忆 | ✅ | ✅（团队 + 本队成员） | ✅（仅自己） | ❌ |
| 硬删除记忆 | ✅ | ❌ | ❌ | ❌ |
| 结算 Effect | ❌ | ❌ | ❌ | ✅ |

> 「人类」的写动作必须带确认令牌（目标 hash + 影响面 hash + 一次性 nonce + 过期），
> 见 `application/human-actions.ts`。

## 2. 工具面

| 角色 | 工具数 | 说明 |
|---|---|---|
| 队长 | 15 | 建队、建/读任务、工作流、聘任、认领、裁决、完成、知识（清单以生成契约 [tool-surface](tool-surface.md) 为准） |
| 成员 | 3 | `myteam_progress` / `myteam_evidence` / `myteam_submit_review` |

两侧注册表物理分离：队长 preset 里没有成员工具，成员会话里没有队长工具（`t12` 断言）。

## 3. 内置角色能力（项目引导时写入）

| 角色 | 工具允许 | 工具拒绝 | 用途 |
|---|---|---|---|
| 实现者 | read / write / edit / pwsh / bash | — | 按验收标准实现 |
| 审查者 | read / pwsh / bash | write / edit | 独立复核，不重写 |

成员的能力只能**收窄**：规则在 `plugin/src/domain/definitions/role.ts` 的 `narrowCapabilities()`
（子集校验，越界报 `CAPABILITY_ESCALATION`），聘任时由 `plugin/src/domain/teams/member.ts`
应用——收窄失败即拒绝聘任，不存在「先建了再说」；配置不能绕过收窄。

## 4. 能力五态（对某个具体动作）

| 状态 | 含义 | 面板显示 |
|---|---|---|
| allowed | 明确允许 | 可用 |
| denied | 明确拒绝 | 禁用 + 原因 |
| narrowed | 允许但被父级收窄 | 可用，标注范围 |
| unknown | 拿不到判断依据（如未接入全局库） | **显示「未知」，不显示「允许」** |
| n/a | 该身份不适用 | 隐藏 |

## 5. 刻意不做

- 不做「超级身份」：系统只能结算 Effect，不能发起业务动作；
- 不让成员自己完成自己的任务：提交评审 ≠ 裁决通过；
- 不让配置扩大权限：配置只表达限制与偏好；
- 不在工具参数里接受身份：身份只来自会话绑定。
