# 25-交互流程打通审计（2026-11-15）

> 本文是对「整个操作交互流程哪些地方还没打通」的**实测审计**。
> 方法：静态交叉对账（客户端控件 → handler → RPC → 服务端 → 存储）+ 三个独立审计员分段深挖。
> 每条结论都带 `文件:行号` 证据；拿不准的标「未确认」。

## 0. 一句话结论

**主链路是通的，但有 7 处 P0 断点**（点了完全没反应 / 功能不存在），
其中最严重的一条是：**产品定案「任务可以手动删除」，代码里一行都没实现**——
而且当时的变更记录和一条测试都把它写成了「已完成」。

## 2. P0 断点（功能完全不可用）

### P0-1 任务「删除」不存在 —— 产品需求未交付，且被伪装成已完成

**产品定案**：「任务不能手动建，**但是可以手动删除**」。

**实际**：
- 任务详情抽屉只有 3 个动作（重新规划 / 编辑 / 取消），无删除：`plugin/client/src/54-task-detail.js:424-446`
- 服务端无任何 task 删除端点：`plugin/src/panel.ts:1362`、`plugin/src/remote/service.ts:605` 的 marker 列表里没有 `deleteTask`
- 账本无删除类事件：`plugin/src/core/ledger/ledger.ts:35-52` 只有 `task.cancelled`

**而**：`plugin/client/src/79-panel.js:1687` 有一条注释写着「删除仍走任务详情（`mt-taskdel`）」——
`mt-taskdel` 全仓只出现在**这条注释**里。

**并且**：`plugin/test/t53-p3-client.test.ts:86` 的断言是
```ts
assert.ok(source.includes('mt-taskdel'), '任务删除入口保留')
```
——唯一匹配源就是那条注释。**测试全绿 ≠ 能力存在**。

**影响**：误建的任务只能 `cancelled`（不可逆终态，`plugin/src/host.ts:1820-1823` 拒绝重开），
永远留在看板「未完成」列。

### P0-2 全局页的角色详情永远停在「加载中」

**现象**：侧边栏打开面板（`mode='global'`）→ 点任意角色卡 → 抽屉只有「关闭」+「加载中…」。

**原因链**（三处叠加）：
1. `plugin/client/src/79-panel.js:67` —— `if (scope !== 'project' || projectRoot) return undefined`
   → 全局页**永不解析** `projectRoot`，恒为 `''`
2. `plugin/client/src/79-panel.js:389` —— `if (!openRole || !projectRoot) { setRoleDetail(null); return }`
   → 详情数据恒为 `null`
3. `plugin/client/src/66-role-detail.js:9` —— `data === null` 走「加载中」空态

**影响**：全局角色库只能看卡片标题，看不到提示词 / 技能 / MCP / 在册情况。

---

### P0-3 全局页 5 个按钮点了完全没反应（`setScope` 是空实现）

`plugin/client/src/79-panel.js:7`：
```js
const setScope = react.useCallback(() => {}, [])
```

CHG-201 把作用域改由「挂载点」决定后，`setScope` 退化成空函数，但**调用方没跟着改**：

|---|---|
| 全局页「＋ 新建角色」 | `79-panel.js:641-647` |
| 全局页角色详情「复制到项目 / 编辑」 | `79-panel.js:758`、`761` |
| 技能 & MCP 页「绑定到角色」 | `79-panel.js:616` |
| 项目「角色」tab 的「↗ 全局」 | `79-panel.js:938` |
| 建团向导脚注「管理预设库」 | `79-panel.js:2015-2021` |

**叠加原因**：`RoleFormDrawer` 只渲染在项目页 return 末段（`79-panel.js:1986`），
全局页 return 块（`622-766`）里根本没有它。

### P0-4 归档回放的「看证据 / 看门禁」点击无反应

`plugin/client/src/79-panel.js:974` 的 `onOpenTask` 落到 `setOpenTask(...)`，
但**归档团队在 `teamsPage` 里是提前 return 的**（`79-panel.js:948-976`），
而唯一渲染 `TaskDetail` 的地方在非归档分支（`79-panel.js:1279-1311`、`1923`）。

`content` 只在 `projectTab === 'teams'` 时取 `teamsPage`（`79-panel.js:1957`）
→ 归档分支一 return，`openTask` 再也不会被消费。

**触发点**：`67-archive-replay.js:234`、`:47`、`63-audit.js:71`
**影响**：归档回放的任务历史只能看标题，任何下钻都进不去，且**无任何 toast 提示**。

### P0-5 多团队项目里，知识提案「采纳 / 驳回」发到错误团队

**提案列表是全区聚合的**：`plugin/src/host.ts:519-544` 遍历**每个** teamId 的 `ledger.jsonl`，
所有 `knowledge.proposed` 都进 `proposals`，每条带 `teamId` 字段。

**但客户端把「当前选中团队」传给了写端点**，`proposal.teamId` 从未被使用：
`plugin/client/src/79-panel.js:1178-1188` → `58-cost-tab.js:170-175` → `api.adoptKnowledge({ teamId, ... })`
→ 服务端按该 teamId 找提案：`plugin/src/host/knowledge.ts:89-90` → `MT_VALIDATION`

**影响**：一个项目两个团队时，A 团队的提案在 B 团队 tab 里点「采纳」必然报错。
单团队项目不受影响。

### P0-6 名册「移除」带子成员时必然失败（二次确认丢 `cascade`）

`plugin/client/src/51-roster.js:38-44`：
```js
let r = await api.memberOp({ ..., confirm: op === 'remove' ? false : undefined, ...(cascade ? { cascade: true } : {}) })
if (r?.status === 'confirm-required' && window.confirm(...)) {
  r = await api.memberOp({ teamId, memberId: member.id, op, confirm: true })   // ← cascade 丢了
}
```

服务端先返回 `confirm-required`（`plugin/src/host.ts:2318-2320`），
**之后**才做派生树检查（`host.ts:2325-2327` → `releaseOrder(..., cascade=false)`）
→ 第二次调用必然被 `MT_HAS_CHILDREN` 拒。

**影响**：用户点了两次确认、看到「将一并释放 N 个子成员」，然后失败。
`suspend` / `archive` 不受影响（不需要 confirm）。

### P0-7 建团向导第 2 步「组建名册」被静默丢弃

`plugin/client/src/69-team-create.js:21` → `68-prompt.js:24-32`：
```js
buildTeamPrompt({ name, goal, presetId, presetName })
```
**没有 roster 参数**。用户在 `rosterSection`（`69-team-create.js:133-156`）加的、
从 `librarySection`（`161-190`）挑的、`removeAt` 删的，全部只进 `rosterOverride` 状态参与渲染，
**不进入任何写路径**。

**连带**：选「不套预设」时 `pickPreset('')` 把 roster 清成 `[]`（`69-team-create.js:37-38`），
但队长最终仍按 `submit_plan` 的 `presetTeamRoster('triad')` 兜底（`plugin/src/host/plan.ts:143-146`）
→ 用户「不套预设」的意图同样失效。
