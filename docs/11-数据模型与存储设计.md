# 11-数据模型与存储设计

> 2026-10-31 · PM 产出（CHG-44）· 对应 PRD v2.13 §4.1、docs/04 契约、docs/03 五域划分。
> 目标：把「功能之间的内部关系」和「数据存在哪里、谁写谁读、怎么重建」一次说清，作为实现与审查的共同口径。

## 0. 一句话模型

> **一个工作区（workspace）= 一个 `.team-workplace/`；权威只有账本（append-only），其余全部是可重建的派生数据或外部配置。**

```
Workspace ──1:N── Team ──1:N── Member / Task / Message / KnowledgeProposal
                     │
                     ├── Task ──N:N── Task（deps 依赖）
                     ├── Task ──1:N── Attempt（claim 生命周期）
                     ├── Task ──1:N── GateResult（review/verify/archive）
                     └── Team ──1:N── TokenBucket（按天 × 成员）
Role（三层来源）──1:N── Member        Preset（团队模式）──1── Captain Session ──1── Team（由队长创建）
KnowledgeEntry ──N:N── Task（evidence 指针：task: / file: / session:）
```

## 一、功能关系（能力地图）

面板与工具不是并列的功能清单，而是围绕「**一个团队 = 一份账本 + 一组角色实例 + 一条任务流转链**」组织的三圈：

```
外圈：入口与生命周期
  团队模式预设会话（唯一入口）
    └─ 队长工具：submit_plan / approve / spawn / escalate 裁决 / disband
        └─ 面板：查看（只读）+ 管理（approve/disband/member ops）

中圈：执行与流转
  任务 DAG（deps） → claim/attempt → progress/evidence → gate → done/deliverable
        ↑                                  ↓
   escalate → re-scoping → rescope/split/abort    knowledge.proposed → 队长审 → 知识库

内圈：支撑数据
  账本（唯一权威） → 投影/视图 → 面板、任务 thread、审计、归档
  角色库（内置只读 / 用户全局存档 / 项目运行时真相）
  成员私有记忆（memory.md + notes/，仅该成员可见）
  团队知识库（config/knowledge，全员按索引按需读）
  token 侧车（按天 × 成员，读侧车不进账本）
```

### 1.1 功能 ↔ 数据 关系表

| 功能 | 写什么 | 读什么 | 存储位置 | 层 |
|---|---|---|---|---|
| 团队创建（队长会话） | `team.created` | 角色库 | `state/teams/<id>/ledger.jsonl` | L0 |
| 角色创建/复制（create-role 技能 / 内置复制） | 角色 JSON | 内置/全局/项目角色 | `config/roles/<id>.json` | L2 |
| 计划（澄清/暂存/批准） | `plan.*` 事件 | 投影 | ledger | L0 |
| 任务执行（claim/progress/evidence/done） | `task.*` 事件 | 投影、门禁配置 | ledger | L0 |
| 门禁（review/verify/archive） | `task.gate.result` | 产物落位、证据块 | ledger + 交付物文件（docs/） | L0 |
| 面板看板/流程/详情 | 只读（唯一写入口是 planAction/postComment/disband） | 投影快照、token 侧车 | 内存投影 + `tokens.json` | L1/L2 |
| 角色↔团队关系视图 | 只读 | `describe()` 的 members（roleId/instanceName/status） | 内存投影 | L1 |
| 知识库（提案/采纳/演化） | `knowledge.*` 事件 + 条目 md | 条目 + 索引 | `config/knowledge/` | L0+L2 |
| 成员记忆 | memory.md / notes/ | 仅成员自身 | `members/<id>/memory/` | L2（不入库） |
| token 计量 | `tokens.json`（派生） | tokenUsage 投影 | `state/teams/<id>/tokens.json` | L0→L2 派生 |
| 归档/解散 | `team.disbanded` + 归档快照 | 归档目录 | `archive/` | L3 |
| 导出/分享 | 只读导出 | 投影 | `export/` | L3 |

**关系规则（不变量）**
1. 面板永远不是事实源：所有数字从账本投影派生（I2）。
2. 角色 ↔ 成员是 **引用 + 快照**：成员 spawn 时把角色定义快照进 `identity.json`（C3 不可变），角色后续修改不影响已召唤成员。
3. 任务 ↔ 成员是 **attempt 级绑定**：`task.claimed(attemptId)`，成员被释放/撤销即 attempt 失效（FR-4.3）。
4. 知识 ↔ 任务是多对多证据关系（`task:` / `file:` / `session:`），不是归属关系。
5. token 与账本**分离**：token 是派生计量，不进账本、不进模型上下文（F2）。

## 二、存储分层（L0~L3）

| 层 | 性质 | 内容 | 写入方 | 丢失后果 | 重建方式 |
|---|---|---|---|---|---|
| **L0 权威** | append-only、fsync | `ledger.jsonl`（每团队一份） | 唯一写者 `TeamService.commit()` | 团队历史丢失 | 备份/归档恢复 |
| **L1 派生** | 内存为主 | `TeamProjection`（成员/任务/提案/inbox 状态） | 每次 commit 增量 `applyEvent`（O(1)，先算后写） | 无（重启重建） | 冷启动全量重放 ledger（O(n)，唯一恢复路径） |
| **L2 侧车/配置** | 可重建或人工维护 | `tokens.json`、`config/knowledge/`、`config/roles/`、成员 `identity.json`/`memory/` | host 进程 / 成员 / 用户 | 计量或记忆丢失 | tokens 由账本重算；角色/知识为外部输入；identity 是快照（不可重建，只能从 spawn 事件重放） |
| **L3 归档/导出** | 快照 | `archive/<teamId>/`、`export/` | 解散/导出动作 | 只影响回看 | 从 ledger 重新导出 |

**关键取舍（已定，勿再反复）**
- 不落 `team.json`：ADR-002 R2 决策 B **已实装（CHG-59）**——每次 commit 在投影副本上增量 `applyEvent`（O(1)，折返失败不落账本），冷启动全量重放一次；`team.json` 在 M2 规模无收益（R37 已关闭，重估触发=10k+ 事件或启动变慢）。
- 写路径顺序固定为「校验 → 副本 apply → 账本 append → 切换投影」：账本永不出现不可重放的脏事件（旧顺序 append→全量 fold 有此隐患）。
- 权威运行时不重写：只有三种受控场景（格式 clean-break 迁移 / 密钥物理清除 / 崩溃 torn tail 截断），见 §4.1 存储决策。
- 缓存整文件写是刻意的：tokens.json / index.json 有界、可随时重建。

## 三、目录结构（实测路径）

```
<workspaceRoot>/

    ├── structure.md                     # 队长维护的结构约定（FR-10.1）
    ├── config/                          # ✅ 建议入库（随仓库共享）
    │   ├── team.config.json             # 行为配置（看板列/泳道/limits/gates；FR-9.1）
    │   ├── roles/<roleId>.json          # 项目角色（运行时唯一真相；内置/全局靠复制进入）
    │   ├── presets/<presetId>.json      # 团队预设（名册模板；M2）
    │   └── knowledge/                   # 团队知识库（FR-17）
    │       ├── <topic>.md               # 条目（frontmatter + 正文）
    │       └── index.json               # 索引缓存（派生，可从 md 重建）
    ├── state/                           # ❌ 运行时状态（gitignore）
    │   ├── teams/<teamId>/
    │   │   ├── ledger.jsonl             # L0 唯一权威（append-only）
    │   │   ├── tokens.json              # L2 token 侧车（按天 × 成员四桶）
    │   │   ├── team.config.json         # 团队级生效配置（建团时按团队模板落盘；CHG-55）
    │   │   └── members/<memberId>/
    │   │       ├── identity.json        # 成员快照（角色快照，C3 不可变）
    │   │       └── memory/
    │   │           ├── memory.md        # 私有记忆（跨会话；不入库）
    │   │           └── notes/           # 成员自建笔记（R26：成员自己 mkdir）
    │   ├── logs/                        # 运行日志（终态清理）
    │   ├── scratch/                     # 临时区（不入库、不审计；成员自建）
    │   └── teams.json                   # 工作区团队索引（派生，CHG-45；可全量重建）
    ├── archive/<teamId>/                # L3 归档（解散时快照：账本 + 名册 + 花费）
    └── export/                          # L3 人读导出（审计/分享，入库自定）
```

**全局目录（workspace 之外，仅存档）**

```
$DSH_HOME/myteam/roles/<roleId>.json     # 用户全局角色库（CRUD；运行时不被直接读取）
$DSH_HOME/myteam/workspaces.json         # 跨工作区团队索引（CHG-45：全局看板离线数据源）
```

## 四、文件 schema

### 4.1 ledger.jsonl（L0，每行一个事件）

```jsonc
{
  "seq": 42,                 // 连续递增，从 0 开始；断号=损坏
  "ts": 1793431212000,       // 单调时间戳（ms）
  "actor": "lead",           // "lead" | "member:<id>" | "human" | "host"
  "type": "task.claimed",    // 39 型白名单（ledger.ts EVENT_TYPES）
  "payload": { "teamId": "default", "taskId": "t-3", "memberId": "m-1", "attemptId": "a-1" }
}
```

- 首事件必须是 `rules.version.adopted`（校验规则版本〔I3〕）。
- 崩溃处理：只截断尾部半行；中部坏行是 QA-1 已知缺陷（M2 修复）。

**事件分组（39 型）**：team（created/disbanded/updated）· plan（clarify/staged/revised/approved/discarded）· member（spawned/released/archived/restored/interrupted）· task（created/updated/cancelled/rewired/claimed/assigned/attempt.revoked/progress/evidence/completed/failed/escalated/rescoped/participate/participation.released/proposal/proposal.resolved/deliverable/gate.result）· message（sent/consumed）· knowledge（proposed/adopted/revised）· rules.version.adopted。

**CHG-73 任务投影新增字段**（全部可重放，由 fold 从事件算出）：

| 字段 | 来源 | 用途 |
|---|---|---|
| `lastEditAt` | `task.updated` / `task.rescoped` 的 ts | 「最近改动」与排序 |
| `rescopeCount` | `task.rescoped` 计数 | 面板「第 N 次重规划」 |
| `evidenceStale {since, fields}` | 结构字段（AC/交付物/依赖/角色/任务类型/门禁链）编辑于证据之后 | 看板徽标 + 详情横幅「证据已过期」；`task.evidence` 清除 |
| `cancelledAt` / `cancelReason` / `cancelDownstream` | `task.cancelled` | 取消留痕（终态不可逆） |

**CHG-76 批次语义**：批量操作（`myteam_batch_task_op` / `myteam_create_tasks` / 门面同名端点）把一批事件用同一 `batchId` 串起来——`task.created` / `task.cancelled` / `task.rewired` 的载荷都可带 `batchId`，审计页按它可整批复盘。**没有新增事件类型**（仍 39 型）：批量只改变"几条边一起动"，不改变单条事件语义。

### 4.2 tokens.json（L2 派生）

```jsonc
{
  "version": 1,
  "teamId": "default",
  "updatedAt": 1793431212000,
  "note": "估算口径：缓存命中使精确分摊不可得（REV-5）",
  "days": { "2026-10-31": { "m-1": { "uncachedInput": 0, "cacheRead": 0, "cacheWrite": 0, "output": 0, "calls": 0 } } },
  "totals": { "m-1": { /* 四桶合计 + hitRate */ } }
}
```

- 由账本中 `task.progress/completed` 携带的用量重算（`rebuildTokens`），**不是**权威。
- 面板只读侧车（F2），永不进模型上下文。

### 4.3 角色 `config/roles/<id>.json`

```jsonc
{
  "id": "developer",
  "name": "开发者",
  "description": "开发侧执行：claim/done 证据块/受阻 escalate",
  "isCaptain": false,
  "systemPrompt": "……",
  "toolPolicy": { "allow": ["myteam_*"], "deny": ["subagent_*"] }, // C5：只能收窄
  "skills": ["filesystem"],
  "mcpAllowlist": ["docs"],
  "model": { "provider": "magpie", "model": "wps-lingxi/deepseek-v4.1-flash" },
  "origin": "builtin:developer",   // fork 自内置时写入；项目/全局复制同样标注
  "version": 1
}
```

三层来源：内置（插件包，只读）· 全局（`$DSH_HOME/myteam/roles/`，CRUD）· 项目（`.team-workplace/config/roles/`，**运行时唯一真相**）。复制进入项目后才可编辑；成员 spawn 时整体快照进 `identity.json`。

**同名副本口径（CHG-74）**：同一个 `id` 可能同时存在多份——内置只读那份、全局个人资产那份、项目库那份（spawn 会按"引用即复制"把内置角色复制进项目库）、项目自身角色那份。口径三条：

1. **目录不隐藏任何一份**（隐藏会让人以为自己的角色丢了），只标注 `shadowedBy`（谁让我让位）；
2. **生效优先级**：`project > project-role > global > builtin`——运行时真相恒为项目库（R13）；
3. **详情按生效条目返回**（`getRoleDetail` 命中生效那份 + 附 `shadowed`/`editable`），否则会出现"项目里改的那份，详情却显示内置定义"。

| 副本来源 | 可编辑 | 是否运行时生效 | 让位标注 |
|---|---|---|---|
| 项目库 `config/roles/<id>.json` | ✅ 直接改 | ✅ 唯一生效 | — |
| 项目自身角色 `config/project-role.json` | ✅（独立卡） | 聘任时按项目库解析 | 被同名项目库条目压过时标 `shadowedBy:'project'` |
| 全局 `$DSH_HOME/myteam/roles/<id>.json` | 复制到项目后改 | ❌ | 被项目库压过时标 `shadowedBy:'project'` |
| 内置（插件包） | 复制到项目后改 | ❌ | 被项目库/全局压过时标 `shadowedBy` |

### 4.4 成员 `identity.json`（L2 快照，C3 不可变）

```jsonc
{
  "id": "m-1", "roleId": "developer", "instanceName": "dev-1",
  "sessionId": "session-…", "status": "active",
  "roleSnapshot": { /* 复制时刻的完整角色定义 */ },
  "skills": ["ui-design"],            // 成员级技能 allowlist（CHG-54；CHG-58 起为运行时硬隔离）
  "mcpAllowlist": ["filesystem"],     // 成员级 MCP allowlist（同上）
  "spawnedAt": 1793431212000
}
```

**能力隔离（CHG-58）**：spawn 时按 `identity.json` 的 `skills/mcpAllowlist`（空则回退角色声明）在成员 agent 作用域内收窄——MCP 用 `tools.restrict({deny})` + 执行期 `guard`，技能用同名占位 provider（`modelInvocable:false`、正文不可读）；allowlist 为空 = 不启用隔离。隔离是运行时视图，不写账本。

### 4.5 知识条目 `config/knowledge/<topic>.md`（L2，人工/提案维护）

```markdown
---
id: db-schema
title: 数据库结构说明
tags: [db, schema]
audience: []            # 空=全员
core: false
evidence: ["file:docs/schema.md#L12", "task:t-3", "session:session-…"]   # 每条必带
contributor: lead
updated: 2026-10-31
proofCount: 3
staleSince: "2026-10-31"   # 任务证据触及 tags 时写入；refine 采纳后清除
---
正文……
## 演化
- 2026-10-31 refine：此前认为 X，t-3 证实 Y（by lead）
```

索引 `index.json` 是派生缓存（id/title/tags/core/unverified/stale），可从 md 重建；注入成员提示词的只有索引摘要（≤40 行），正文按需 `myteam_read_knowledge` 读取。

### 4.6 `config/team.config.json` 与 `state/teams/<teamId>/team.config.json`（L2，配置）

看板列与列归并、泳道维度、DAG 选项、limits（maxMembers/maxTasks）、gates 默认链、taskTypes（任务类型 → 门禁链）。合并层级：内置默认 < 项目 `config/team.config.json` < 团队级 `state/teams/<teamId>/team.config.json`；逐层应用（非法/不覆盖终态的层被忽略并告警，已生效浅层保留），数组整条替换（R12）。

**CHG-55 团队级配置**：`myteam_submit_plan({presetId})` 在 `TeamService` 首次构造前，把模板声明的 `board/pipeline/gates/taskTypes` 原子写入（tmp + rename）团队级 `team.config.json`；`TeamService` 构造时按「项目层 → 团队层」读取（来源 `team`/`project`/`default`），`create_task` 缺省 `gateChain` 按生效 `taskTypes` 展开，看板（在线/离线）与设置页直接消费同一份配置。模板未声明的段落不落文件，仍继承项目层/插件默认。**CHG-57**：`myteam_reset_team_config` 删除团队级文件并重建配置缓存（退回项目层/默认）。

**模板写路径（CHG-57）**：`myteam_save_preset / myteam_copy_preset / myteam_delete_preset` 只写 `.team-workplace/config/presets/<id>.json`（原子写），内置模板随插件分发、只读；模板只在建团时快照，删除/修改不影响已建团队。

### 4.7 `state/teams.json` 与 `$DSH_HOME/myteam/workspaces.json`（L2 派生索引，CHG-45）

```jsonc
// 工作区级：.team-workplace/state/teams.json
{
  "version": 1,
  "workspaceRoot": "E:/Workplace/extension/dsh-myteam",
  "updatedAt": 1793431212000,
  "teams": [{
    "teamId": "default",
    "goal": "做登录页",
    "state": "active",                    // draft | active | archived | discarded
    "createdAt": 1793430000000,
    "updatedAt": 1793431212000,
    "members": [{ "roleId": "developer", "instanceName": "dev-1", "status": "active" }],
    "counts": { "tasks": 6, "done": 2, "running": 1, "members": 3 }
  }]
}

// 跨工作区级：$DSH_HOME/myteam/workspaces.json
{
  "version": 1,
  "updatedAt": 1793431212000,
  "workspaces": {
    "E:/Workplace/extension/dsh-myteam": { "workspaceRoot": "…", "updatedAt": 0, "teams": [ /* 同上 */ ] }
  }
}
```

- **派生、可重建**：`scanWorkspaceIndex()` 从各团队账本全量折叠重建（坏行容错）。
- **写入时机**：`TeamService.commit` → `afterCommit` → 单团队 upsert（不重扫全部账本）；宿主构造时若索引缺失则全量重建。
- **原子写**：`<path>.tmp` + rename；写失败只 warn，不阻断 commit 主路径。
- **消费方**：门面 `listTeams()` 合并"存活会话（online）∪ 索引（offline）"，面板全局列表与角色↔团队关系视图只读使用；不进模型上下文（F2）。

## 五、关键数据流

### 5.1 一次提交（写路径唯一收敛点）

```
Lead/Member 工具调用
   → TeamService.commit(draft)
        ① checkDomain() 领域校验（拒绝式，抛错之前返回错误码）
        ② validateEvent() schema + seq 连续性 + actor
        ③ appendEvent() 原子追加 + fsync
        ④ applyEvent() 增量折叠投影（M2 起；当前为全量 fold）
        ⑤ sidecar：tokens.json（按需）、knowledge index（按需）
```

面板写操作（planAction / postComment / disband）走**同一条** commit 管线，绝不直写文件（ADR-006）。

### 5.2 一次任务生命周期（任务面 ↔ 数据面）

```
task.created ─→ backlog ─(deps 全 done)→ ready ─(claim/attempt)→ in_progress
   → progress(用量落 tokens)  → evidence(证据块) → completed → gate:review/verify/archive
   → task.deliverable + gate.result → done
异常：attempt 撤销（陈旧) / escalate → re-scoping → rescope|split|abort
知识：done 时 knowledgeDraft → knowledge.proposed → 队长 adopt → knowledge.adopted（+条目 md）
```

## 六、一致性与恢复

| 场景 | 规则 |
|---|---|
| 单写者 | 所有写经 `TeamService.commit()`；无并发写者 |
| 崩溃 | 尾部半行截断（保留完整事件）；seq 由尾部推算 |
| 中部坏行 | **已知缺陷 QA-1**：当前会在坏行处中断，之后事件静默丢失；M2 修复为受控截断或 loud fail |
| 派生重建 | tokens/index 可从账本重建；投影冷启动全量重放；角色/知识以文件为准 |
| 归档 | 解散 = `team.disbanded` 事件 + 快照到 `archive/<teamId>/`；归档后不再接受写 |
| 迁移 | 只允许显式 cutover 工具；宿主绝不静默迁移；SQLite 触发条件见 R30 |
| 安全边界 | 面板只读；成员沙箱外能力由宿主约束；记忆/知识不入模型自动注入（按需读） |

## 九、面板信息架构的模型增量（CHG-64~68 设计 → CHG-69 已实现）

> 以下为 25 屏设计稿（design/）确立的模型口径，**已由 CHG-69 落地**（账本事件 / 投影 / 视图 / 门面 / 工具 / 面板全部接线，212 绿）；实现以本表 + ADR-011 为准，契约见 docs/04 §2/§3。

1. **角色 schema 增量（CHG-64/69，已实现）**：`RoleDefinition.interestWords?: string[]`（≤8 个短词；生成时随 `roleSnapshot` 固化进 identity.json 快照——C3 不变量）；消费方 = 角色卡 chips / 任务详情「派单依据」/ 审计追溯。校验：`assertValidRole` 拒绝超量/空串（不静默截断）。
2. **聘任记录（队员，CHG-64/69，口径不变）**：沿用既有 identity.json 快照模型，语义更名——队员 = `{teamId, roleId, instanceName, snapshot, joinedAt}` 的关系记录；**不新增实体，不改落盘结构**；面板只在 `RoleCatalogView.memberships` 里把它按角色聚合成「在册情况」（仅 project / project-role 统计聘任）。
3. **参与关系（CHG-67/69，已实现）**：账本 +2 型 `task.participate` / `task.participation.released`（payload：`taskId, participantTeamId, role, memberIds?`）；投影 `participations[taskId] = { leadTeamId?, teams: { teamId: {teamId, role, memberIds, seq, ts} } }`。
   - **归属**：任务账本仍由主责团队持有（物理分布不变）；参与边由主责团队写入自己的账本，协作方不持有任务副本。
   - **隐含主责**：`task.created` 即写 owner=lead 参与边；旧账本无参与事件时视图回落 `{owner, lead}`（向后兼容）。
   - **约束**：主责只能是本团队（跨团队主责需迁移账本，当前不支持）；协作不能是本团队；主责不可释放；`role=lead` 迁移时旧主责自动降级为协作。
   - 消费方 = 看板「参与团队」轨 / 任务卡团队 chip（实线主责 · 虚线协作）/ 任务详情「参与团队」/ 团队「参与任务」tab。
4. **作用域目录（CHG-66/69，已实现）**：全局角色库 `$DSH_HOME/myteam/roles`（既有）+ 项目角色库 `.team-workplace/config/roles`（既有）+ **项目自身角色** `.team-workplace/config/project-role.json`（schema 同角色、origin 标 `project-role`；`listRoleCatalog` 并列返回，不写进项目角色库目录）；团队与任务为项目层数据（账本已有）。
5. **任务实体归属（CHG-67/69，已实现）**：账本物理分布不变（仍按团队记 ledger.jsonl），主责团队持有任务；跨团队聚合读由门面 `getProject` 完成——在线团队走隔离服务 getBoard、离线团队折叠账本、索引缺失时扫 `state/teams` 目录补齐；任务键用 `teamId/taskId` 复合键避免跨团队同名冲突。
6. **依赖图数据（CHG-68/69，已实现）**：新增 `core/tasks/graph.ts`（`buildTaskGraph` 最长路径分层 + 边集 + 环容错；`dependencyChain` 上下游闭包），随 `BoardView.graph` / `ProjectView.graph` 下发；面板用 SVG + marker 箭头渲染，横向按列、竖向按行，几何由数据算出（卡片定宽），竖向按父节点期望位置对齐以减少交叉。
