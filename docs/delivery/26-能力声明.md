# 能力声明（security:capabilities）

> `dsh_plugin_check` 的 `security:capabilities` 规则会扫描代码里的写文件 / 读环境 / 跑命令 /
> 开网络四类调用，列出命中点。它**只报告、不判断**，所以永远是一条 warn。
> 本文逐条说明这些命中点是什么、边界在哪，供审查者自己核对。

## 结论先说

| 能力 | 是否真的具备 | 说明 |
|---|---|---|
| 写文件 | **是** | 这是插件的核心职责：项目事件账本、写者租约、全局库、记忆库都要落盘 |
| 读环境 | **是** | 读 `DSH_HOME` / `DSH_INSTALL_DIR` 来定位宿主安装目录与全局库根 |
| 跑命令 | **否（误报）** | 命中的是 `node:sqlite` 的 `db.exec()`，那是 SQL API，不启动任何进程 |
| 开网络 | **否（误报）** | 命中的是浏览器端 `fetch`，目标是**同源**的面板路由，不连外部 |

## 逐条

### 写文件 —— 真的具备，且是必需的

命中点（`src/` 侧）：

| 文件 | 写什么 | 边界 |
|---|---|---|
| `infrastructure/event-store/file-store.ts` | 项目事件账本 `events/project.jsonl` | 只写 `<项目>/.dsh-myteam/` 内；原子批次 |
| `infrastructure/event-store/writer-lease.ts` | 写者租约 `state/writer.lock` | 同上；不是业务事实 |
| `infrastructure/fs/project-manifest.ts` | `manifest.json` | 同上 |
| `infrastructure/fs/project-destroy.ts` | 删除项目数据 | **人类专属**，需一次性令牌 |
| `infrastructure/global-library/write.ts` | `$DSH_HOME/myteam/` 下的全局定义 | **人类专属**，需一次性令牌 |
| `infrastructure/memory-store/sqlite-memory.ts` | `memory/memory.db` | 只写本项目内；硬删除仅人类 |
| `infrastructure/migration/v1/convert.ts` | 迁移候选目录 | 写到**独立目录**，不动旧工作区 |
| `application/global-edit.ts`、`contracts/publication.ts` | 全局库编辑 / 发布 | 人类专属 |
| `scripts/build-lib.mjs` | `lib/` 构建产物 | **只在开发/发版时跑**，不随插件装载执行 |

关键约束：**所有写路径都限定在 `<项目>/.dsh-myteam/` 或 `$DSH_HOME/myteam/` 之内**，
没有一处写用户工作区的其它位置。全局库的写一律要人类令牌（见 `docs/contracts/permissions.md`）。

### 读环境 —— 真的具备

| 变量 | 用途 | 缺失时 |
|---|---|---|
| `DSH_HOME` | 全局库根 `$DSH_HOME/myteam` | 回落 `~/.dsh` |
| `DSH_INSTALL_DIR` | 定位宿主安装目录里的 `zod` / `@deepseek-ai/dsh-typert-protocol` | 明确降级（记 warning、不注册），不让 profile 起不来 |
| `MYTEAM_DESIGN_DIR` | 覆盖设计稿目录（调试用） | 走默认候选路径 |

不读任何密钥、token 或用户隐私数据。

### 跑命令 —— **误报**

命中的是 `src/infrastructure/memory-store/sqlite-memory.ts` 里的 `this.db.exec(...)`。
`DatabaseSync` 是 Node 内置的 SQLite 绑定，`exec()` 执行的是 **SQL 语句**，不启动子进程。

真正会起子进程的只有 `scripts/build-lib.mjs`（构建脚本，用 `spawnSync` 跑 `node --check`），
它**不在插件装载路径上**——宿主装载的是 `index.js` → `lib/composition/host.mjs`，
构建脚本只在 `npm run build` 时执行。

### 开网络 —— **误报**

命中的是 `client/client.js` 里的 `fetch`：

```js
const url = new URL(`__myteam/${method}`, document.baseURI)
const response = await fetch(url, { method: 'POST', credentials: 'same-origin', ... })
```

`document.baseURI` 是当前页面自己的地址，所以这是**同源**请求，打的是宿主自己注册的
面板路由 `/__myteam/<method>`（见 `composition/panel.ts` 的 `PANEL_ROUTE_PREFIX`）。
不连任何外部服务，也不带出项目数据。

## 为什么不改代码去消掉这条 warn

`security:capabilities` 是**报告规则**，不是缺陷判定：它把「这个插件能做什么」摆给用户看，
让用户自己决定要不要装。为了消掉一条 warn 去把写文件改成别的形态，等于掩盖真实能力——
那才是安全问题。

真正该做的是**让能力可核对**，也就是本文。审查者可以按上面的表格逐条 grep 验证。
