## A. 安装 v2 到 DSH profile

前置：

- [ ] `bun`/`node` 可用；`cd plugin && node --test test/*.test.ts` 全绿
- [ ] `node scripts/build-lib.mjs` 生成 `lib/`（47 模块）
- [ ] 备份 profile：复制 `C:\Users\Hanes\.dsh\profiles\desktop` 到带日期的备份目录
- [ ] 记录当前已安装的 myteam 版本与 `cordis.patch.yml` 内容

步骤：

1. 构建：`cd plugin && node scripts/build-lib.mjs`；
2. 把 `plugin/`（含 `lib/`、`package.json`、`icon.svg`）放进 profile 的插件目录（与 v1 同位置，先移走 v1）；
3. 更新 profile 的插件声明到 `myteam`，入口 `@dsh-plugin/myteam`；
4. 重启 DSH（不是热重载）：`main` 指向的入口变了，热加载不会替换已加载模块；
5. 打开 DSH Web，验证：
   - 工具箱里出现队长工具（12 个）；
   - 会话里 `myteam_read_board` 返回空看板而不是报错；
   - 面板能读到 `status`（若 RPC 已接）。

失败回滚：

1. 停止 DSH；
2. 还原备份的 profile 目录；
3. 重启，确认 v1 工具恢复；
4. 记录失败点（哪一步、什么错误），不要边改边重试。

## B. 真实 cutover（v1 → v2 数据）

> 已封装为一条命令：`node tools/myteam-cutover.mjs --root <工作区>` 演练；
> 加 `--apply --confirm --backup <目录>` 执行。手工步骤保留在下方作为对照。

前置：

- [ ] `node tools/rehearse-cutover.mjs --root <工作区>` 通过（已通过，11 步）
- [ ] `node tools/myteam-migrate.mjs cutover-plan` 返回「可以切换」
- [ ] 用户逐条确认影响面（重复规则事件、2 个索引孤儿）
- [ ] 停止所有写旧账本的会话/进程

步骤：

1. 备份：把 `.dsh-myteam` 与 `.team-workplace` 复制到独立只读目录；
2. 重新分析并生成候选：`myteam-migrate.mjs candidate --root … --candidate <目录>`；
3. 校验：`cutover-plan` 必须仍返回「可以切换」（源 hash 未变）；
4. 切换：用候选的 `manifest.json` + `events/` 替换工作区的 `.dsh-myteam` 对应文件（不合并、不重写旧账本）；
5. 首次打开：v2 打开项目，确认 seq 连续、团队/成员/任务/知识计数与候选报告一致；
6. 留报告：记录 projectId、来源 hash、跳过事件计数、确认记录；
7. 旧数据保持只读备份，**不随文档一起删除**。

回滚：

- 首次 v2 写入前：从备份还原即可（演练已验证）；
- 首次 v2 写入后：不做自动反向回滚；只能导出 v2 修复，或管理员显式切回并接受这段新写入丢失。
