## 2. 发布前检查（每条都要有输出，不看「大概没问题」）

1. `node tools/verify.mjs` → **VERIFY_OK**（单测、架构门禁、面板/工具/配置契约、文档替换、文档链接）。
2. `cd plugin && node scripts/build-lib.mjs` → `OK — nn module(s)`，且 `lib/build-manifest.json` 的
   `sourceHash` / `clientHash` 与源码一致。
3. `npm pack --dry-run` → 确认打进包的面：`lib/` `src/` `client/` `scripts/` `cordis.patch.yml`
   `icon.svg`；当前 **137 个文件 / 297.6 kB**（解包 1.1 MB）。包体异常变大先查是不是把 `.dsh-myteam/`
   或临时产物带进去了。
4. 客户端入口自检：`node --test plugin/test/t30-client-assets.test.ts`（声明、标签、样式纪律）。
5. UI 渲染冒烟：`node --test plugin/test/t39-client-render.test.ts`（14 屏 + 四条写交互路径）。
6. 写面负路径：`t16` / `t40` / `t41` 全绿（令牌一次性、影响面变化失效、agent 不能确认、记忆参数先验）。
7. 隔离验收：`node tmp/verify-iso.mjs` → **ISO_VERIFY_OK 46/46**（独立 `DSH_HOME` + profile + 端口，
   含准入/读面/写面/客户端资产/清除，见 [25-隔离验收记录](25-隔离验收记录.md)）。

> PowerShell 里 `npm pack --dry-run | Select-Object -Last n` 可能报非零退出（管道截断），
> 以 `npm run prepack` 与 `node scripts/build-lib.mjs` 的退出码为准。

## 3. 安装 / 升级 / 回滚

```powershell
# 本仓库自测：web profile 直接 link，改完 build:lib + 刷新页面即可
dsh plugin --profile web list

# 发布后的安装（不要手改 profile 文件）
dsh plugin --profile web add dsh-plugin-myteam@2.0.0
```

回滚：`dsh plugin --profile web remove dsh-plugin-myteam` 后装回上一版本；插件不在 host 上时
面板路由整段消失，不影响宿主其它功能。

## 4. 发布后验证（人点，脚本替代不了）

1. 宿主启动后左栏出现 **myteam**（全局库），会话顶栏出现 **团队视图**。
2. 打开一个队长会话的「团队视图」：概览有数、九栏都能切、不出现「通道未接入」。
3. 点「新任务」建一条 → 看板立刻多一张卡；点开卡片能提交门禁裁决（仅 `review` 状态显示表单）。
4. 团队栏选中团队 → 「解散团队」第一次只出影响面，第二次才执行。
5. 定义栏「发布」→ 预览引用与覆盖 → 确认后 `$DSH_HOME/myteam/roles/*.json` 与
   `audit/global-operations.jsonl` 各多一条。
6. 浏览器控制台无报错；面板请求都是 `POST /__myteam/*`，未带 `sessionId` 的只有
   `globalLibrary` / `globalAudit`。

## 5. 已知限制（发版说明里要写清，不要藏）

- **真实会话端到端**已在隔离实例里验过：用宿主自己的 `session.create` 造活会话，10 个读方法 +
  团队/任务详情全部读到真数据并与磁盘对账，写面 8 条正负路径全绿（[25](25-隔离验收记录.md)）。
  第 4 节仍是**人眼**验收：界面观感、深色、窄宽、真实点击，机器判不了。
- **界面**：左栏全局库那一屏已用隔离实例截图核对（浅/深/414px），并据此修掉三处：
  导航轨继承宿主灰底导致深色对比度 3.54:1、窄宽时摘要/状态条被裁、页脚「回到对话」重复。
  会话「团队视图」九栏的视觉**仍待人点一次**（自动化进不去会话列表）。
- **i18n 未做（有决策，不是漏项）**：宿主的 locale 服务强制「两种基准语言齐全」才能注册词典，
  半套英文会让发布包直接不可用，所以 2.0.0 只出中文；接入路径、键表分组与验收判据见
  [26-i18n决策](26-i18n决策.md)。
- **设计稿 24 页 ↔ 客户端 14 屏**：设计稿里的依赖图（p-dag）、泳道（p-lanes）、审批队列
  （p-approval）、归档（p-archive）等目前是「同一份数据的不同切法」，还没有独立屏；数据面已够，
  差的是渲染。
- **记忆硬删**只能由人类在面板发起，`hard: true` 会直接删行，没有二次确认弹层（面板上是
  `confirm: true` 一次提交）。
