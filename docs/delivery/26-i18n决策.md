# i18n 决策：2.0.0 只出中文，接入方案已定

> 结论先说：**2.0.0 不接 i18n**，客户端文案保持中文；接入路径与判据写在下面，等下一个版本做。
> 这不是"忘了"，是因为宿主的 locale 机制**强制双语齐全**，硬凑会变成半套。

## 为什么现在不做

宿主的 locale 服务（活契约，`client/Service` → `locale`）里，注册词典只有两种形态：

| 形态 | 要求 |
|---|---|
| `register(ns, dicts)` 类型化形态 | **必须同时给出两种基准语言**（中/英），缺一个直接编译不过；这是"双语平衡"的硬约束 |
| `register(ns, locale, dict)` 非类型化 | 单语言可以注册，但只能用于语言包/合并表之外的命名空间，宿主 UI 不认它的一致性 |

也就是说，"先把中文抽出来、英文以后再说"这条路在类型化 API 上走不通。客户端现有文案
约 200 条（导航 14 条、页头与状态、九栏各自的空态与提示、写交互表单与错误文案），
要一次性给出中英两份还要保证键集完全一致——这是独立一轮的工作量，
不适合塞在发版收尾里做，而且任何漏键都会让发布包直接不可用。

## 接入方案（下一版照这个做）

1. **命名空间**：`myteam`。键按语义分组，与现有常量一一对应：
   `view.team`（会话标签）、`nav.*`（九栏/五栏）、`head.*`、`status.*`、`empty.*`、
   `form.*`（新任务/裁决/发布/解散）、`error.*`（错误码 → 人话）。
2. **取用方式**：客户端在 `apply(ctx)` 里 `const t = (ctx.get('locale') as ... )?.bind('myteam')`
   （`ctx.get('locale')` 需判空，见契约里的 `optional` 访问）；拿不到就回落到内置中文表，
   保证老宿主也不白屏。
3. **标签**：注册槽位时 `label` 现在是 `() => '团队视图'`，改成 `() => t('view.team')`。
   宿主会在每次投影时重读 thunk，所以切语言不需要重新注册。
4. **持续同步**：正文里的文案不是槽位 label，切语言时要重渲染 —— 订阅
   `locale/change`（或 `ctx.slots.installLocale` 给的 `subscribe`）后 `forceUpdate`。
5. **语言包**：若将来加第三种语言，用 `addLanguage`，其 `fallback` 链必须终止于英文。
6. **测试**：中英词典键集必须完全相等（用集合比较，不是"抽样看几个"）；
   再补一条渲染冒烟：切到 `en` 后 tab 标签与页头取英文值。

## 验收判据（做了才算数）

- 宿主里切语言 → 会话标签、页头、空态、表单标签**全部**跟着变，不出现中英混排；
- 词典缺键时 `register` 直接报错（机制自带），不是运行期显示 key；
- 没有语言服务的老宿主：中文照常显示（回落路径要单独测）。

## 什么时候做

排在"会话「团队视图」九栏的人眼验收"之后、下一版开始前。理由：先把界面本身定下来，
再做文案抽取，避免同一批字符串改两遍。
