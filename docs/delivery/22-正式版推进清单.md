### 写方法（4）

两种确认方式（`panelWriteKind`）：`token` 先预览影响面换一次性令牌、再凭令牌执行；
`direct` 直接带 `confirm: true` 执行，由域内状态校验兜底。

| 方法 | 确认方式 | 底层 |
|---|---|---|
| `teamDisband` | `token` | `previewTeamDisband` / `confirmTeamDisband`（`team.disband`，人类专属） |
| `captainTakeover` | `token` | `previewCaptainTakeover` / `confirmCaptainTakeover`（`captain.takeover`，人类专属） |
| `definitionPublish` | `token` | `requestDefinitionPublication` / `confirmDefinitionPublication`（`definition.publish.confirm`，人类专属） |
| `gateVerdict` | `direct` | `recordVerdictCommand`（要求 `status==='review'` + `attemptId` 为当前 Attempt） |
| `taskCreate` | `direct` | `createTaskCommand`（无依赖即 `ready`，有依赖停在 `planned`） |
| `memoryRemember` | `direct` | `rememberMemory`（人类不带 `memberId` 写团队 bank）；先验参数再开库 |
| `memoryForget` | `direct` | `forgetMemory`（默认软删留痕，`hard: true` 才真删；硬删仅人类） |

共享夹具 `plugin/test/fixtures/review-task.ts`：建队 → 任命 → 建任务 → 认领 → 进度 → 证据 →
提交评审，返回 `{ runtime, taskId, attemptId }`，`dispose()` 自清临时目录。

## 已核对并更正的一条判断

原计划里的「计划批准」在 v2 **没有落点，不做**：`plan.staged` / `plan.approved` 只存在于
**v1 账本**（`infrastructure/migration/v1/analyze.ts` 识别它们用于迁移），v2 的事件类型里没有
`plan.*`，也没有 Plan 实体；`plan.approve` 只是 `policy.ts` / `human-authorizer.ts` 里遗留的
动作位，全仓没有生产者。v2 的「计划」就是 `run.created` 一次实例化出的任务图——建完即生效，
没有草稿态。需要人类把关的地方是门禁裁决（已实现）与全局发布（见上）。

## 不要做的事（已经踩过）

- 不要在 `application` 里 import `infrastructure`：架构门禁会红，正确做法是端口注入
  （`GlobalLibraryPort` / `MemoryStorePort` 就是范例）。
- 不要把写动作塞进只读方法表：面板契约里只读方法不接受 confirm 语义。
- 不要手改 profile 文件：装/卸插件一律 `dsh plugin --profile web add|remove`。
- 不要把 `plan.approve` 当成待实现功能（v2 无 Plan 实体，见上）。
- `memoryDbPath(rootDir)` 返回的是**相对路径**（`memory/memory.db`），打开库时要用
  `join(rootDir, memoryDbPath(rootDir))`。传相对路径会在进程 CWD 下建出一个游离的
  `memory/` 目录（本轮踩过一次，已清理）。
