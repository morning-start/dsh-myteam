# 动作卡片：已挂起（代码保留）

> 结论：**默认不挂载**，保证插件正常可用；等宿主提供 `actionCards` 服务后再启用。
> 决策时间：2026-11-22。相关代码全部保留，并有测试。

## 为什么挂起

| 事实 | 影响 |
|---|---|
| 宿主把 `@deepseek-ai/dsh-action-cards` 当作**实验 bundle** 分发，`@deepseek-ai/dsh-base` 与 web 模板都不含它 | 默认 profile 里 `actionCards` 服务不存在，kind 行会一直 `pending` 并每次启动告警 |
| 把该包名直接加进 profile 的 `bundles` | 报 `declares no dsh.bundle in its package.json`，不是可挂载的 bundle |
| npm 上可安装的 `0.2.2-alpha.2` 与本机运行时 `0.2.2-rc.5` | 依赖版本不满足，安装被 DSH 拒绝（需 alpha 系列） |

因此默认的 `cordis.patch.yml` **不包含** `myteam-human-skill`、`myteam-human-cards` 两行。

## 保留了什么

| 文件 | 作用 | 测试 |
|---|---|---|
| `plugin/src/composition/human-cards.ts` | 卡片动作处理器：确认前重算影响面并比对 `targetHash`；`cancel` 不写业务 | `t33` |
| `plugin/src/composition/human-card-kind.ts` | 宿主接线：从 `DSH_INSTALL_DIR` 解析 zod、注册 kind、record 决策 | 依赖宿主服务，未跑 |
| `plugin/src/composition/human-actions-skill.ts` | 随包 skill，内容说明「先预览再 propose_action」 | 已实测：挂载后技能目录可见 |
| `plugin/src/application/tool-specs.ts` 的两个预览工具 | `myteam_preview_disband` / `myteam_preview_takeover`，只读、返回 `targetHash` | `t34`（断言不写事件） |
| `plugin/package.json` 的 `./human-cards`、`./human-actions-skill` 导出 | 供启用时挂载 | 构建产物存在 |

这些代码默认不会被任何 `cordis.patch.yml` 行加载；文件保留、构建仍会生成对应 `lib/` 模块，不影响正常使用。

## 将来怎么启用

1. 确认运行时已提供 `actionCards` 服务（profile 能解析到它，且 `dsh --profile <名> --dump-config` 里出现该服务所在行）；
2. 在 `plugin/cordis.patch.yml` 加两行（放在 `myteam-commands` 之后）：

   ```yaml
   - id: myteam-human-skill
     name: 'dsh-plugin-myteam/human-actions-skill'
     inject: ['skills']
   - id: myteam-human-cards
     name: 'dsh-plugin-myteam/human-cards'
     inject: ['actionCards', 'agents', 'workingDirectory']
   ```

3. 重新构建并重启：`node scripts/build-lib.mjs`，然后重启 profile；
4. 验证：
   - 日志出现 `myteam.card.registered`；
   - 技能目录出现 `myteam-human-actions`；
   - 队长按 skill 指引调用 `propose_action` 后，对话里出现卡片。
5. 卡体渲染：`@deepseek-ai/dsh-client-ui-action-cards` 提供统一框架，但**每种 kind 的卡体可能还需要客户端组件**；如果卡片显示为空壳，就需要补客户端半边。

## 回退

删掉上面两行、重建、重启即可回到当前状态；不需要改任何业务代码。
