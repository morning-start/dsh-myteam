## 缺陷分级与关闭标准

- **P0**：核心流程不可用 / 数据丢失 —— 阻塞发布，清零后才能发布。
- **P1**：主要功能受损但可绕行 —— 清零后才能发布。
- **P2**：轻微问题 —— 有规避方案即可发布，登记回归清单。

## DoR（可开发条件）

- 需求有目标、场景、优先级、MVP 边界
- 有业务验收标准和非功能要求
- 有技术方案、接口/数据契约、估算
- 风险与依赖已登记（06）
- QA 验收用例草案已就绪

## DoD（可发布条件）

- 功能验收通过
- 非功能项达标或有明确豁免
- P0/P1 清零，P2 有规避方案
- 文档、监控、告警、回滚方案齐全
- QA 验收报告签字，PM 业务确认，TL 技术确认
