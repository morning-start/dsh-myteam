# 存储结构与资源路径（重整理稿）

> **状态**：定稿（2026-11-08，用户裁决：①建全局团队库 ②技能归属 myteam「队长」预设 ③资源按角色依附）。
> **地位**：myteam 的**目录契约与数据结构**唯一权威；与 docs/17（项目级存储架构）冲突时以本文为准并回改 17。
> 关联：docs/19（资源模型与能力矩阵）、docs/16（插件贡献契约）、docs/18（配置 Schema）。

## 1. 三条裁决（用户原话 → 落地）

| # | 裁决 | 落地含义 |
|---|---|---|
| R1 | **要有全局团队库** | 新增 `$DSH_HOME/myteam/teams/<teamId>.json`（**团队定义**，非运行态）；`copy_team` / `publish_team` 以它为源与靶 |
| R2 | **技能归属 myteam「队长」预设** | 技能目录挂 **myteam 自己的预设根**：`$DSH_HOME/myteam/presets/myteam-captain/skills/<skillId>/SKILL.md`；**不进** `$DSH_HOME/skills/`（全局技能目录），**不污染其它预设** |
| R3 | **角色是最小资源单位，子代理 / 会话依附角色** | 成员（子代理）与会话 id **挂在角色实例名下**：`state/teams/<teamId>/members/<memberId>/`（会话 id 写成员卡，不散落全局） |

**隔离铁律**：myteam 只读宿主技能与其它预设；**写**只能写 `$DSH_HOME/myteam/**` 与 `<workspace>/.dsh-myteam/**` 两个根。任何工具都不得写 `$DSH_HOME/skills/`、`$DSH_HOME/presets/<other>/`。

## 2. 两个根（唯一入口 `storeLayout()` / `myteamHome()`）

```
① 全局根（跨项目）        $DSH_HOME/myteam/
② 项目根（工作区内）      <workspace>/.dsh-myteam/
```

> 解析唯一入口：`core/workspace/layout.ts` 的 `storeLayout(workspaceRoot)`；**禁止**在别处拼路径（docs/17 纪律）。

## 3. 全局根结构（`$DSH_HOME/myteam/`）

```
myteam/
├── config.json                    # 全局层配置（三层合并的「全局」层，docs/18）
├── roles/                         # 全局角色库（可聘任）
│   └── <roleId>.json              # RoleDefinition（origin=global）
├── teams/                         # ★ CHG-132 新增：全局团队库（团队定义，非运行态）
│   └── <teamId>.json              # GlobalTeamDefinition（见 §5.1）
├── presets/                       # 团队模板（建团蓝图）
│   ├── myteam-captain/            # ★ myteam 自有预设（技能挂这里）
│   │   ├── preset.json            # 预设元数据（id/name/version/roles/tools）
│   │   └── skills/                # ★ myteam 技能（R2：只属于本预设）
│   │       └── <skillId>/
│   │           ├── SKILL.md       # 技能正文（frontmatter: name/description）
│   │           └── assets/        # 可选附件
│   └── <otherPreset>/preset.json
├── plugins/                       # 插件贡献物（docs/16 契约 v1，只读）
│   └── <pluginId>/plugin.json
└── history/archive/               # 归档快照（disband 产物，只读）
    └── <teamId>/{team.json,tokens.json,members/,artifacts/}
```

**为什么技能放 `presets/myteam-captain/skills/`**：技能是**预设资产**（跟着预设走、随预设版本升级），不是全局共享物。放这里天然满足「不污染其它预设」——只有装 `myteam-captain` 预设的会话能看见。

## 4. 项目根结构（`<workspace>/.dsh-myteam/`）

```
.dsh-myteam/
├── project.json                   # 项目元信息（workspaceRoot / createdAt / myteamVersion）
├── config/
│   ├── team.config.json           # 项目层团队配置（三层合并的「项目」层）
│   ├── project-role.json          # 项目自身角色（不属于任何团队，可被聘任）
│   ├── roles/                     # 项目角色库（origin=project，**运行时只认这份**）
│   │   └── <roleId>.json
│   ├── teams/                     # 项目团队模板（preset 的项目层）
│   │   └── <presetId>.json
│   └── knowledge/                 # 知识库（采纳后的条目）
│       └── <entryId>.json
├── state/
│   ├── workspace-index.json       # 工作区团队索引（list_teams 数据源）
│   └── teams/
│       └── <teamId>/              # ★ 团队运行态（每团队一目录）
│           ├── team.config.json   # 团队层配置（三层合并的「团队」层）
│           ├── ledger.jsonl       # 账本（append-only，唯一权威）
│           ├── tokens.json        # token 侧车（增量桶）
│           ├── charter.md         # 团队章程（structure.md 快照）
│           └── members/           # ★ 成员（子代理）依附角色实例
│               └── <memberId>/
│                   ├── member.json    # 角色绑定 + 会话 id + 技能覆盖（见 §5.2）
│                   └── memory.md      # 成员记忆（可选）
└── history/archive/<teamId>/      # 归档快照（只读）
```

**关键点**：**成员（子代理）与会话 id 不散落**——`sessionId` 只写在 `members/<memberId>/member.json` 里，团队与角色是唯一归属（R3）。

## 5. 数据结构

### 5.1 `GlobalTeamDefinition`（`$DSH_HOME/myteam/teams/<teamId>.json`）

```jsonc
{
  "version": 1,
  "teamId": "global-team-review",       // 全局库内唯一
  "name": "审查团队",
  "goal": "跨项目复用的审查团队定义",
  "charter": "## 章程\n...",            // 可选：团队章程（Markdown）
  "roster": [                            // 名册（角色引用，不复制角色定义）
    { "roleId": "captain",   "instanceName": "captain" },
    { "roleId": "developer", "instanceName": "dev-1", "skills": ["code-review"] }
  ],
  "config": { /* 团队层配置子集：board / pipeline / gates / taskTypes / clarify / memory / audit */ },
  "presetId": "myteam-captain",          // 来源预设（仅记录）
  "origin": "project-copy",              // project-copy | user-authored
  "createdAt": 1731000000000,
  "updatedAt": 1731000000000
}
```

> **不含**：账本、任务、attempt、门禁结果、成员会话 id、token 计量——那些属于运行态（§5.3）。

### 5.2 `MemberCard`（`state/teams/<teamId>/members/<memberId>/member.json`）

```jsonc
{
  "version": 1,
  "memberId": "m-7f3a",
  "teamId": "team-1234",
  "roleId": "developer",              // ★ 归属角色（R3）
  "instanceName": "dev-1",
  "sessionId": "sess-9c2e",           // ★ 子代理会话（只在这里）
  "skills": ["code-review"],          // 成员级覆盖（≤ 角色 skills，只收窄）
  "mcpAllowlist": ["filesystem"],
  "status": "active",                 // active | suspended | released
  "currentTaskId": "task-42",
  "createdAt": 1731000000000
}
```

### 5.3 运行态 vs 定义态（不可混）

| 类别 | 落点 | 可复制 | 可发布 |
|---|---|---|---|
| **定义态**（GlobalTeamDefinition / RoleDefinition / preset） | 全局根 / `config/` | ✅ | ✅（人类专属） |
| **运行态**（ledger / tasks / attempts / tokens / 成员卡 / 归档） | `state/teams/<teamId>/` | ❌ | ❌ |

### 5.4 `SkillAsset`（`presets/myteam-captain/skills/<skillId>/`）

```jsonc
// SKILL.md frontmatter
{
  "name": "code-review",
  "description": "按仓库纪律做代码评审（含 CSS 纪律、测试门禁）",
  "version": 1,
  "tools": ["read", "grep", "pwsh"],   // 该技能需要的工具（只声明，不扩权）
  "mcp": ["filesystem"]
}
```

**装载**：myteam 插件启动时扫 `$DSH_HOME/myteam/presets/<presetId>/skills/*/SKILL.md` → 注册为**本插件的技能**（命名空间 `myteam:`），**不写** `$DSH_HOME/skills/`。

## 6. 三层配置（docs/18 口径不变，只补路径）

| 层 | 路径 | 优先级 |
|---|---|---|
| 内置默认 | 代码常量 `DEFAULT_TEAM_CONFIG` | 最低 |
| 项目层 | `<workspace>/.dsh-myteam/config/team.config.json` | 中 |
| 团队层 | `<workspace>/.dsh-myteam/state/teams/<teamId>/team.config.json` | 最高 |

**全局层**（`$DSH_HOME/myteam/config.json`）**不参与**团队配置合并（团队配置是项目级资源）；它只承载「全局角色库 / 全局团队库 / 预设」的元信息。

## 7. 迁移（`v1 → v2`，CHG-132 内做）

| 变更 | 兼容策略 |
|---|---|
| 新增 `$DSH_HOME/myteam/teams/` | 目录不存在 = 空库；`publish_team` 时按需创建 |
| 新增 `presets/myteam-captain/skills/` | 不存在 = 无自带技能；`list_skills` 返回空 + note |
| 成员卡从「投影内存」落到 `members/<memberId>/member.json` | **读兼容**：无卡片时从账本 fold 出投影（现行为），**写**只在 spawn 时补卡 |
| `sessionId` 收敛到成员卡 | 旧数据（`projection.members[].sessionId`）继续可读；新写入只写卡片 |

**迁移不阻断**：所有新路径都「不存在即空」，不要求用户先跑迁移脚本。

## 8. 与工具面的映射（docs/19 能力矩阵 → 路径）

| 工具 | 读/写 | 路径 |
|---|---|---|
| `list_roles` | 读 | 全局 `roles/` + 项目 `config/roles/` + `project-role.json` + 插件贡献 |
| `copy_role` | 写 | 源（全局/内置/插件）→ `config/roles/<roleId>.json` |
| `publish_role` | 写 | `config/roles/<roleId>.json` → 全局 `roles/<roleId>.json` |
| `list_teams` / `get_team` | 读 | `state/teams/<teamId>/` + `state/workspace-index.json` |
| `copy_team` | 写 | 源团队 → **新** `state/teams/<newTeamId>/`（staging） |
| **`publish_team`（CHG-132）** | 写 | 源团队 → 全局 `teams/<teamId>.json`（**单向**） |
| `save_team_config` | 写 | `state/teams/<teamId>/team.config.json` |
| `list_skills` | 读 | 宿主 `skills` 服务 + **`presets/myteam-captain/skills/`** + 角色绑定 |
| **`create_skill`（CHG-134）** | 写 | **只能** `presets/myteam-captain/skills/<skillId>/SKILL.md` |
| `get_audit` / `get_tokens` | 读 | `state/teams/<teamId>/{ledger.jsonl,tokens.json}` |
| **`export_team`（CHG-133）** | 写 | 快照 JSON → 用户指定路径（默认 `history/exports/<teamId>-<ts>.json`） |
| **`import_team`（CHG-133）** | 写 | 快照 → **新** `state/teams/<newTeamId>/`（**不覆盖**） |
