# 决策记录（ADR）

> 每个文件只处理**一个**主题；标题写清它决定的是什么。
> 状态只能是 `proposed`（还没定）、`accepted`（已定，正在/已经照它做）、`superseded`（被后一份取代，并指向后者）。
> 定了但还没有代码的决策，正文里必须写「实施批次」；已经落地的，指到守着它的测试。

## 规矩

1. **一份 ADR 一个主题**：不要在一份里同时决定「归档」和「记忆清理」两件事；
2. **改了主张就新开一份**：旧的那份标 `superseded` 并链到新的，不要原地改写成另一件事
   （读者需要看到「当初为什么那样定」）；
3. **写明不做什么**：ADR 的价值一半在「决定了不做什么」；
4. 决策落地后，把「实施批次」换成「守着它的测试与代码位置」。
