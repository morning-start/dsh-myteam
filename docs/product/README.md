## 1. 产品定位

myteam 是 DSH 内的通用多智能体团队运行时，让可复用的定义资产与项目内真实协作分离：

- **全局级**：只保存值得跨项目复用的 RoleDefinition、WorkflowDefinition、TeamBlueprint；
- **项目级**：保存本地定义、真实团队、WorkflowRun、任务 DAG、配置、知识与长期记忆；
- **DSH**：管理 Agent/Session、子代理、Skill、MCP、工具连接及执行事实。

核心目标不是“多开几个 Agent”，而是让团队工作在**权限明确、任务可追踪、历史可回放、故障可恢复**的统一项目模型中运行。

## 2. 目标用户

| 用户 | 主要诉求 |
|---|---|
| 项目工作者 | 用自然语言或面板组建团队、分配工作、查看完整进度 |
| 团队负责人/Captain | 组合角色和流程，规划与动态调整任务，处理升级和门禁 |
| 领域成员 | 使用明确的角色能力与权限完成任务、提交证据、沉淀记忆 |
| 插件/资产作者 | 提供可复用 Role、Workflow、TeamBlueprint，而不侵入运行时 |
| 人类审批者 | 控制全局发布、计划批准、队长接管、解散和其他破坏性动作 |

## 3. 当前目标需求

### P0 · 定义资产与复用

1. RoleDefinition 只包含 RoleProfile 与 CapabilitySet，不携带工作流或运行状态。
2. WorkflowDefinition 与 TeamBlueprint 可独立复用、复制和发布，Blueprint 只保存引用。
3. 全局资产必须显式复制到项目后才能实例化；项目副本独立演进。
4. 所有全局写都经过人类专属确认、影响面预览和审计；agent 只能提出发布请求。
5. Skill、MCP、工具连接由 DSH 持有，myteam 只保存引用与收窄规则。

### P0 · 项目协作与任务

1. 一个项目允许多个团队并行，任务直接属于项目。
2. 一个项目只有一张 Task DAG，支持主责/协作团队和跨团队依赖。
3. WorkflowRun 可以覆盖单成员、跨成员和跨团队，但始终复用同一任务模型。
4. 动态增删任务、重接依赖、重分配必须原子、可审计并防止循环依赖。
5. 任务、Attempt、门禁、证据和交付物可跨会话恢复，陈旧执行票据不得继续写入。

### P0 · 一致性与权限

1. 项目定义、配置、知识与运行事实以项目事件日志为唯一业务真源。
2. Captain、Member、Panel 使用同一个 Root Runtime，不各自维护业务 Host 与投影。
3. 项目写者防止物理分叉，Captain Assignment 防止业务指令冲突。
4. 生成配置、知识 Markdown、看板和索引都是可重建派生物。
5. 权限由服务端强制执行，工具隐藏、`confirm:true` 或 `actor:'human'` 不能替代鉴权。

### P0 · 配置、知识与记忆

1. 配置有可回放的有效快照；项目默认、蓝图默认与团队覆盖的生效边界明确。
2. 知识经过提案、采纳和修订策展，正文与历史进入项目事件。
3. 长期记忆以项目 SQLite 为权威，严格校验 bank 所有权，不进入全局。
4. DSH Session Log 是模型执行事实的权威，myteam 不复制第二份会话真相。

### P1 · 可观测与验收

1. 项目看板、任务详情、参与团队和依赖图来自同一投影。
2. 离线与在线读取走同一 Query Service，降级不得伪装成空状态。
3. DSH Web 可完成建队、跨团队 DAG、门禁、打回、重启恢复和队长接管验收。
4. 工具、RPC、事件和错误码等契约在功能设计后生成，不手工维护多份计数。

## 4. 核心用户场景

1. **复用定义**：把全局 Role/Workflow/Blueprint 复制到项目，按本项目需要调整并实例化。
2. **组建团队**：选择 TeamBlueprint 或自定义队形，规划后由用户批准启动。
3. **执行工作流**：从 Definition 创建 Run，将任务分配给一个或多个成员/团队。
4. **动态重规划**：根据阻塞、证据或验收结果调整项目 DAG，保留完整变更历史。
5. **跨团队协作**：一个任务依赖另一个团队的任务，双方在同一项目图中协调。
6. **恢复与接管**：宿主重启、队长离线或成员会话失效后安全恢复，不重复执行未知 Effect。
7. **发布资产**：把项目中验证过的定义经脱敏和影响面预览后，由用户发布到全局。

详细功能流程将在 [../features/README.md](../features/README.md) 所列功能设计中展开。

## 5. 非目标

- 不做全局任务、全局 WorkflowRun、全局运行团队或跨项目任务 DAG；
- 不做全局行为默认配置；
- 不做全局与项目之间的自动双向同步；
- 不把 TeamBlueprint 与 DSH AgentPreset 混为一谈；
- 不把 Role 变成 Workflow，也不把 Skill 变成第二套任务引擎；
- 不代管 MCP 凭据、工具连接或宿主全局技能；
- 不用另一套 Workflow 节点状态复制 Task 状态；
- 不以跳过损坏事件、盲放 Effect 或伪造迁移历史换取“可用”。
