## 一、复检方法（每屏都要走一遍）

1. **先看设计稿** `.debug/ref-<屏名>.png`，在心里列出「这一屏有哪几块、每块的层级/数量/间距」。
2. **再看实现** `.debug/design-<编号>-<屏名>.png`，逐块对照，记下差在哪。
3. 只改**能落到设计稿上的**差异（结构 / 区块顺序 / 列数 / 层级 / 文案 / 控件形态 / 空态）。数据缺失导致的差异（例如团队离线、账本没有该字段）**不要造假数据**，如实留「—」或空态。
4. 改完跑 `node --check plugin/client/client.js` + `cd plugin && node --test test/*.test.ts test/*.test.js`，全绿再报。

# 第二轮复检（CHG-85）：逐元素越界探测

> 用户反馈「UI 还是一片混乱」。上一轮的验收方法有盲区，本轮换工具、换维度再查一遍。

## 一、上一轮为什么漏了

| 盲区 | 说明 |
|---|---|
| **只量页面级滚动条** | 上一轮只量 `documentElement.scrollWidth - clientWidth`。但宿主面板容器 `mP3x-q_centerCol` 是 `overflow-x:hidden` —— **面板内部被裁的内容不会产生页面级滚动条**，量出来永远是 0。 |
| **宽度只测 1600** | 真实桌面 App 的面板宽度不等于 1600（实测面板宽 = 窗口宽 − 285px 侧栏）。窄屏下的塌陷完全没覆盖。 |
| **不区分「被裁」与「可滚到」** | 元素超出容器可能只是「需要横向滚动」（正常），也可能是「被 overflow:hidden 裁掉，永远看不见」（bug）。这两种必须分开判。 |

## 二、新工具

`.debug/overflow-probe.mjs` —— 逐元素判定：

1. 找最近的 `overflow:hidden/clip` 祖先（**裁切者**）与最近的 `overflow-x:auto/scroll` 祖先（**可滚到**）。
2. 元素右边界超出裁切者 > 2px 且不在可滚容器内 → 记 **clipped**（真被裁）。
3. 元素超出面板右边界 → 记 **past**。
4. `scrollWidth > clientWidth` → 内容比容器宽。
5. 自身文本被 `ellipsis` / `-webkit-line-clamp` 吃掉 → 记 **cut**（带 `title` 全文时不算 bug）。
6. 输出完整祖先链（tag / class / 宽高 / overflow / flex / min-width），定位是谁在裁。

配套：`cdp3.mjs` 加 `resize(w,h)`，同一屏在 **1600 / 1280 / 1024 / 900 / 820** 五档下复测（面板实测宽 1315 → 759）。

## 六、第三轮（CHG-86）：跨切面缺陷 + 交互闭环

> 前三轮的分工：CHG-84 逐屏对照设计稿（79 处差异）、CHG-85 逐元素越界探测（7 处真实裁切）、

### 6.1 为什么前两轮的方法漏掉了这些

前两轮都是「截图 ↔ 设计稿」的**静态**比对。CHG-86 的 4 个 P0 全都是**动态通路**问题：

| 缺陷 | 为什么静态截图看不出来 |
|---|---|
| 门禁链死锁 | 任务详情**画得出**「门禁链：review → archive」和两个裁决策略位；只是**没有任何入口能把 verdict 写回账本**。截图上一切正常 |
| 归档视图空壳 | 归档屏**渲染完整**（名册 / 任务历史 / 按天桶 / 账本与产物四段都在），但它渲染的是内存投影，`archive/<id>/` 下的真实文件一个都不存在 |
| token 按天桶只有一行 | 表格**有表头、有数据行**，只是永远只有今天一行 —— 看不出来「应该有多行」 |
| 工具重名越权 | 纯后端注册表问题，UI 完全无感 |

**方法教训**：UI 复检必须同时问两句 ——「画对了吗」（静态）**和**「点得通吗」（动态）。
只做静态比对会系统性漏掉「假按钮 / 空数据源 / 无写回路径」这类缺陷。
