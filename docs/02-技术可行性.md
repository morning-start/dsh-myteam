## T0 探针记录（静态证据，2026-10-25）

> 探针方法：直接解包 DSH 桌面版 0.2.1-rc.3 运行时 asar（`app.asar` → `refs/host-src/dsh/`，16605 文件全量），对 `@deepseek-ai/*` 包的 README（契约层）+ `lib/index.js`（实现层）双重取证。静态证据的可信度高于"未验证假设"，低于运行时冒烟；**M1 第一个开发任务仍建议做一次最小动态冒烟**（创建 1 成员→restrict→followup→whenIdle→dispose），成本半天。
> 注意：探针运行时另有一个环境发现——**宿主 spawn 的子进程（bash/node）不能在工作区内"由 write 工具创建的目录"下新建子目录**（ACL：工作区根 `Everyone:(DENY)(DC)` + `S-1-4-*` 授权 + 用户仅 `(WO,S)`；bash 自建目录可写）。对插件设计的影响：插件以 host 进程身份写 `.team-workplace/` 不受影响；但若成员脚本经 bash 在插件预创建目录中建子目录，可能遇到同类拒绝 → 成员 scratch 区由成员自己 mkdir，不由 host 预创建（R7 关联，登记到 06）。

### T0-① AgentHandle 能力边界（R1）

- **来源**：`dsh-agent/README.md`、`dsh-agent-loop/README.md`
- **创建/恢复**：`ctx.agents.create({sessionId, agentOptions:{provider,model}, setup(agentCtx, agent), parentAgent?, meta?})` / `ctx.agents.resume({resumeSessionId, ...})`，均返回 `AgentHandle`；`handle.dispose()` 拥有唯一拆除权（capability）。省略 `parentAgent` = 运行时根。
- **setup 作用域**：`agentCtx` 上的注册（tools / prompt sections / variables / listeners / **restrictions**）只作用于该 agent，dispose 时回收——这正是 C5 收窄、C6 技能隔离的官方机制（agent preset 也用同一机制）。
- **驱动**：`followup()` 排队下一轮并唤醒；`steer()` 在最近 step 边界插入；`inject()` 只注入不唤醒（下一 step 被 admit 时生效）；`cancel(cause)`；`whenIdle()` 等待完全静默。
- **证据块落账本**：成员会话是持久会话（sessionPersistence 挂载时），插件可从成员 session 日志读工具调用事实——但成员会话日志属宿主 session 体系，myteam 账本仍应只存引用。
- **结论**：PRD FR-3.1/3.5/4.4/NFR-7.3 的机制前提**全部成立**，API 名称与 PRD 书写一致。

### T0-② 子代理池关系（R1b/R6）

- **来源**：`dsh-subagent/README.md`（Activation capacity 节）+ `dsh-subagent/lib/index.js` L1027-1053（`ActivationPool.reserve`）、L1672-1680（`materialize`）、L1755（`rootPool`）、L1815-1826（创建走 `ctx.agents.create/resume`）
- **关键事实**：
  1. `maxActiveSubagents` 默认 8，**池按根父（root parent）建、整棵父树共享**（`rootPool(parent)` + `liveLineage` 向上解析）；root 自身不占槽；**超限直接抛 `ACTIVATION_LIMIT_REACHED`，不排队**。
  2. **池挂在 subagent 服务（`dsh-subagent`）上，不是 `ctx.agents` 注册表上**——grep 证实 dsh-agent/dsh-agent-loop 无任何 pool/activation 检查。**插件直接 `ctx.agents.create()`（不带 parentAgent 或带 parentAgent 均可）不经过 ActivationPool，不受 maxActiveSubagents=8 约束**。
  3. 但 dsh-subagent 内部创建子代理也是调 `agents.create`（L1815）——即**通道同源、池只管 subagent 管理器经手的 activation**。
- **对 PRD 的影响（重要修正）**：
  - R6 的"成员创建占池 8 上限"**不成立**——myteam 成员走 `agents.create` 直连，不吃 `ACTIVATION_LIMIT_REACHED`。maxMembers=6 的真实约束从"宿主池余量"变为"模型并发成本与上下文管理"（REV-1 的 6 仍合理，但理由变了）。
  - 成员若再嵌套 spawn（memberMaxDepth=0 禁止），需成员会话内**没有** subagent 委托工具，否则嵌套子代理会占成员自己的池——C5 工具收窄天然覆盖（成员业务工具收窄后不含 subagent 工具）。
  - 保留风险：`agents.create` 的并发数无宿主硬上限 ≠ 无限并发可行；**插件必须自己实现并发上限**（maxMembers 承担此责），创建失败路径可重试可报告的 P0 要求不变。
- **结论**：R6 降级（池冲突不成立），R9 降级；新增设计约束"插件自管并发上限"。

### T0-③ tokenMeter 持久化/读面（R10）

- **来源**：`dsh-token-meter/README.md` 全文 + `lib/index.js` L349-430（projection 定义）、L685-722（TokenMeter 类）
- **关键事实**：
  1. **无任何持久化**：包内无 fs/writeFile 调用；状态是内存 WeakMap（per-session fold）+ sessionProjections 投影。README 明确 "Sessions remain in memory unless a persistence backend is added"（session 层）——tokenMeter 自身不落盘。
  2. **读面**：`measure(session, requestHeader?)` → `{totalTokens, surfaceTokens, nodes}`；`estimateMessage(message)`；投影键 `tokenUsage`（**四桶 `uncachedInputTokens/outputTokens/cacheReadTokens/cacheWriteTokens`**，与 REV-5 官方三桶口径对齐：uncached input + cacheRead + cacheWrite + output + 命中率可派生）、`contextPressure`（pressureTokens/projectedTokens/contextWindow）、`contextBreakdown`（system/tools/message 构成）。
  3. **重放确定性**：measure 重放持久日志、零模型调用、深冻结快照、O(surface)。
  4. **修复口径注意**：README 明确 heuristic（4 字符/token）对 CJK/JSON schema **严重低估**；provider usage 仅在 canonical envelope 匹配时复用。
- **结论**：PRD FR-8.2 假设"tokenMeter 仅实时读、无持久化，插件自行落 tokens.json 侧车"**成立**，且按天桶聚合必须插件自做（tokenMeter 只给 totals，不给时间桶）。R10 **关闭**。REV-5 的"官方三桶"实为四桶（多一个 uncachedInput），账本侧车 schema 按四桶设计。

### T0-④ 成员级 MCP 注入/过滤（R21）

- **来源**：`dsh-mcp-client/README.md` + `dsh-tools/README.md` L85 + `dsh-skill/README.md` L84 + `dsh-skill-filesystem/README.md`
- **关键事实**：
  1. MCP 工具以 `mcp__<serverName>__<tool>` 命名注册进**全局** `ctx.tools`（"Independent Agent scopes may reuse the same namespace"——MCP 插件自身按 scope 隔离，但宿主配置的 MCP 落全局层）。
  2. `agentCtx.tools.restrict(filter)` 支持掩码相交，可按成员收窄——**掩码按 `mcp__<serverName>__` 前缀过滤技术上可行**。
  3. Skill 注册表是 host+per-scope 分层（与 tools 同构）：`agent.ctx.skills.registerProvider()` 的注册落在调用上下文的 scope 层，**只对该 agent 可见**——C6 成员级技能隔离通道确认存在。dsh-skill-filesystem 支持 `includeDefaultRoots:false` + 自定义 roots，可实现"插件内置只读 + 成员私有 notes/skills/ + 角色绑定"的扫描根组合（FR-3.6 前提成立）。
- **对 R21 的修正**：问题从"宿主能否按成员过滤 MCP"变为"**插件能否枚举宿主已连接的 MCP server 清单以生成掩码**"——`ctx.tools.schemas(scope)` 返回全量可见 schema，按命名约定前缀即可枚举 `mcp__*` 工具。**未连接的 server 无工具注册**，allowlist 中标"未连接"的数据源 = 角色 allowlist − 已注册前缀集合。
- **结论**：R21 **大部分消解**（机制通道存在）；动态冒烟确认"restrict 掩码对 `mcp__` 前缀通配的支持方式"（掩码是名单还是 glob，实现时确认，README 未展开 filter 语法）。降级路径仍保留。

### T0-⑤ team 预设注册面（R23）

- **来源**：`dsh-agent-preset/README.md` + `dsh-agent-preset-registry/README.md` + `dsh-plugin-manager/README.md`
- **关键事实**：
  1. preset = 普通 Cordis 插件行（`@deepseek-ai/dsh-agent-preset`，config: `{id, plugins[], name?, description?, order?}`），声明即进 roster；registry 管 revision 与会话绑定，**会话日志记录 preset id，重启恢复用当前定义、缺定义拒绝**。
  2. "新 preset 或覆写 shipped preset = bundle patch：向 profile 插入一行 dsh-agent-preset，经 plugin_manager 安装"——**myteam 插件在自己的 bundle patch 中声明 team preset 行是官方支持的路径**。
  3. preset 的 `plugins[]` 子行挂什么工具/技能/系统提示都行（"声明式选择 Agent 的 tools、prompt sections 和 skills"）——**team preset 携带 myteam_* 工具注册 + 队长提示词 + create-role 技能可行**。
  4. preset 会话 spawn 子代理：subagent provider 的 `agentPreset` 独立选项（"In-process spawn accepts an independent `agentPreset`"）；**冷恢复保留 persona 与 toolFilter**。子代理走 subagent 通道时受 ActivationPool 管（见 T0-②），但成员经 `agents.create` 直连不受。
  5. 限制：preset 不是安全沙箱（YAML/插件可执行宿主代码）；用户覆写会**整行替换**子列表；旧 revision 不跨重启保留。
- **结论**：FR-10.1 v2.2 形态成立。注意点：①preset 更新影响后续新建会话、不追溯运行中会话（与 C3 不可变快照思想一致）；②myteam 的 preset 行需声明 `disabled: false` 确保装载。R23 **关闭**（静态面确认 + 冒烟兜底）。

### T0-⑥ 程序化创建指定预设的新会话并注入首条消息（R25）

- **来源**：`dsh-api-session-controller/README.md` + `lib/typert.host.js` L227-241（create）、L1125-1144（prompt）
- **关键事实**：
  1. `session.create({workspaceId|cwd, sessionId?, agentPreset})`：**agentPreset 参数原生支持**——"重用 Session 时替换其记录的 preset；省略用配置默认"。响应返回实际 sessionId 与运行的 preset。
  2. `session.prompt({sessionId, requestId, mode:'queue'|'steer', content:[{type:'text',text},...]})`：注入首条消息，requestId 幂等（重复提交返回原受理）。
  3. create 的重用规则：命名 sessionId 空白可复用；`session/conflict`（跨目录）与 `session/agent-busy`（子代理路由占用）显式报错。
- **结论**：FR-16.3 handoff 完整版**可行**：`create({agentPreset:'myteam-captain', ...})` + `prompt()` 两步。R25 **关闭**。M2 不需要降级方案（保留"复制摘要"作为离线兜底文案即可）。
