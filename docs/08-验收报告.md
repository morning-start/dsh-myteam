### 10.5 事故记录：`client.js` 编码损坏与还原

改 §10.4 的两条 CSS 时用了 PowerShell `Get-Content -Raw` + `Set-Content -Encoding UTF8`；**PS 5.1 默认按 ANSI(GBK) 读 UTF-8 文件**，于是 835 KB 的 `client.js`（含 800 KB 未提交改动）全文变乱码。

还原路径（可复现）：

1. 该页面在写坏**之前**已加载过模块 → 用 CDP `Debugger.getScriptSource` 取回浏览器手里那份原文（6,410,315 字符的合并 bundle）；
2. 按 `window.__ModuleLoader__.load({ id: 'dsh-myteam' })` 边界切出模块，去掉 bundle 分隔符 `;` + 换行；
3. 结果 **835,413 B**，与写坏前记录的大小**逐字节相等**；再重放 CSS 修复。

**教训**：①改大文件一律用 Node / read-write 工具，不用 PS 的 `Get/Set-Content`；②GBK 往返**不是**可逆变换（.NET 编码器会 best-fit 丢字符），Python `gbk` 也救不回 PUA 区——别指望「反向转码」。
