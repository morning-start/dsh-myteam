# docs — 项目文档

> 本目录是 myteam 的项目知识资产：**人读、随代码 review、可检索**的文档。运行时状态（账本 / token / 成员记忆 / 归档）在项目目录下的 `.dsh-myteam/`，**永不进本目录**（裁决表见 [PRD §4.2](../dsh-myteam-requirements.md)，现行目录契约见 [17-项目级存储架构](17-项目级存储架构.md)）。

## 边界：什么不该放进 docs/

判断准则是「受众 + 生命周期」，不是「谁产生的」（[PRD §4.2](../dsh-myteam-requirements.md)）。

| 内容 | 落点 |
|---|---|
| 任务夹产物（PRD / 技术方案 / QA 报告 / 验收结论） | [docs/myteam/](myteam/)（`<yyyyMMdd>-r<N>-<slug>/`，随收口提交） |
| 团队配置（看板列 / 流水线 / 成员模板 / 角色 / 知识） | `.dsh-myteam/config/`（**入库**，不含凭据） |
| 任务与依赖（账本） | `.dsh-myteam/tasks/<teamId>/ledger.jsonl`（**入库**，唯一权威） |
| 归档 / token 计量 / 成员私有记忆与笔记 | `.dsh-myteam/history/` |
| 索引 / scratch 草稿 / 插件运行日志 | `.dsh-myteam/state/` |
| 人可读导出快照 | `.dsh-myteam/export/` |

- **永不进 `docs/`**：`ledger` / `tokens` / `identity` / `memory`——机器状态与隐私。
- **禁止第二事实源**：`docs/` 不出现账本副本；交付物正本只在 `docs/`，`.dsh-myteam/` 只存引用。
- **不往项目根写规则**：上传纪律住在 `.dsh-myteam/.gitignore` 自己身上（CHG-102）。

## 命名与编号约定

| 形态 | 约定 |

| 清单类文档 | 不带编号（如 [agent-team-practices-checklist.md](agent-team-practices-checklist.md)），因为它是**输入材料**而非阶段产出 |

## 变更纪律

1. **先改文档，再登 CHG**：任何范围 / 架构 / 验收标准的变化，先改对应文档，再在 [09-变更记录](09-变更记录.md) 登一条变更单（模板见该文开头）。
2. **不手改生成的段落**：`docs/04` 的错误码表由脚本生成；`docs/09` 的编号只增不改。
3. **历史快照不追平**：[10-实现说明-阶段3](10-实现说明-阶段3.md) 与 [08](08-验收报告.md) §1 的计数是各自时点的口径，与当前真值不同是**预期**，不要为了「看起来一致」去改历史数字。
4. **新增文档先看编号**：`00`~`17` 是按流程阶段编的；补一份文档就接着编号，并在本页「文档全表」补一行（否则等于没写）。
