# design-v2 — 插件 UI 设计稿（全局库 / 项目工作台分域）

> 按 [新架构](../docs/architecture/01-系统架构.md) 重画：**左侧栏入口 = 全局库（myteam）**，**会话顶栏「团队视图」标签 = 当前项目的工作台**。
> 两个作用域各有自己的导航轨，不再把全局资产和项目运行态混在一个面板里。视觉仍完全跟宿走（`--dsh-*`、14px 正文、1px 细线卡、不加重阴影）。
> 静态稿，`file://` 直开，无构建、无依赖。

## 作用域怎么落

依据 [产品基线](../docs/product/README.md) 与 [系统架构 §3](../docs/architecture/01-系统架构.md)：

| | 左侧栏入口（全局） | 会话标签页（团队视图） |
|---|---|---|
| 存什么 | 可复用的 `RoleDefinition` / `WorkflowDefinition` / `TeamBlueprint` + 全局写审计 | 团队、成员、`WorkflowRun`、项目任务 DAG、项目定义副本、配置、知识、记忆、审计、迁移 |
| 不存什么 | 团队 / 任务 / Run / 知识 / 记忆 / 配置 | 全局定义的正文（只存 `origin` 与副本） |
| 谁能写 | 只有人类确认后写（`$DSH_HOME/myteam`） | 队长、成员按权限提案与执行；破坏性动作要人类确认 |
| 导航 | 概览 · 角色 · 工作流 · 蓝图 · 发布 | 概览 · 任务 · 团队 · 流程 · 定义 · 知识 · 记忆 · 审计 · 设置 |

## 角色怎么点进去（卡片 → 详情 → 定义）

角色的信息分三层，每层只回答一个问题，不做成一张大表：

| 层 | 屏 | 一张卡 / 一屏回答什么 | 怎么进来 |
|---|---|---|---|
| 团队 | `p-teams.html` | 这个团队现在什么状态（队长、名册、蓝图来源、Run） | 概览的团队卡 / 左侧「团队」 |
| 名册 | `p-roster.html` | **这个人现在在做什么**：任务与 Attempt、技能与模型、深度与子成员 | 团队卡「名册」 |
| 名册树 | `p-roster-tree.html` | **结构**：谁派生谁、深度是否到上限、释放会影响谁 | 名册页切换条 |
| 角色详情 | `p-role.html` | **实例**：在跑什么、能力被收窄成什么样、记忆 bank、暂停 / 归档 / 移除的影响面 | 点任意名册卡或树里的名字 |
| 全局定义 | `g-role.html` | **定义**：设定、Allow/Deny、SkillRef、被谁引用、版本历史与项目副本三态 | 角色卡的「查看全局定义 →」/ 角色库卡片 |

约定：

- **一张卡只放「一眼要判断的」信息**：身份（头像 + 名字 + 角色 + 深度）、正在做什么、两三个能力 chip、一行计数。更细的都在详情里。
- **实例与定义分开**：`p-role` 是成员实例（可暂停、可移除，有会话与 attempt）；`g-role` 是角色定义（可发布、可下架，有版本与 hash）。两者互相有出口，但不混在一屏。
- **返回路径写在面包屑里**：角色详情的面包屑是「名册 / 团队 / 名字」，全局定义是「全局库 / 角色 / 名字」，右上角另有一个显式返回。
- **危险动作留在详情**：暂停、归档、移除、下架都放在右列底部，写清影响面，走两段确认（设计稿里不弹层，避免遮住会话）。
- **跨域只一处**：项目侧只在「角色定义」块里链到全局；全局侧只在「在团队里看实例」块里链回项目，不做双向乱链。

## 这一版的关键规则

- **作用域先于导航**：全局页只出现定义与发布；项目页只出现运行与项目定义副本。两侧导航轨内容不同，就是为了让人一眼知道自己在哪一层。
- **状态分开表达**：`有更新` / `可发布` / `已分叉` / `一致` 是四个独立 chip，不压成一个「已过期」；`origin` 与 `baseHash` 用等宽字直接露出。
- **人类专属动作单独一屏**（`p-approval` 与 `g-publish`）：先影响面、再确认；界面明说 `confirm: true` 不是授权，确认令牌绑定目标 hash 与一次性 nonce。
- **Effect 与事实分层**：审计页把 `requested / accepted / completed` 三态写出来；看板与索引都标注来自同一投影。
- **记忆不是知识**：`p-memory` 用 bank 卡片，写明成员只能读写有权的 bank，跨 bank 删除一律拒绝。
- **沿用上一轮**：68px 图标轨、字号 12/13/14/16、`--mt-muted` 的对比度、1px 线 + 无阴影、深色整段换值。

## 怎么看

1. 双击任一 `.html`。全局入口 `g-overview.html`（DSH 左侧栏「myteam」），项目入口 `p-overview.html`（会话顶栏「团队视图」标签）。
2. 两个作用域之间是有意互链的：项目「定义」「发布」「迁移」会把全局页当作下一跳，反之全局页不会链回项目运行态。
3. `p-dag.html` 末尾有一小段脚本按节点真实位置画连线；跨团队边用虚线强调色。
4. 深色：浏览器切换深色模式，或给 `<html>` 加 `data-theme="dark"`。

实现顺序建议：先做查询投影与只读页（概览 / 任务 / DAG / 审计），再做写用例（计划批准、门禁裁决、发布确认），最后接迁移页。颜色只从 `--dsh-*` 与 `--mt-*` 取，不要写新的十六进制。
