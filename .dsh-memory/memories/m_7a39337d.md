## 功能名
拆分巨型源码文件的导入清单确定法（编译器驱动）

## 生效条件
需要把**单个大文件**里的若干顶层声明搬到**新文件**，且原文件的 import 语句分散在多处（不是集中在文件头 30 行）。

## 子功能
- 识别「哪些符号必须在新文件里 import」
- 识别「哪些导出必须从新文件转发回原文件以保持对外 API」

## 执行
**不要写脚本用正则搬代码。** 2026-11-15 在 `plugin/src/host.ts`（4,377 行）上做了五次尝试，五次失败，每次都是「修好一个坑、暴露下一个」：

| # | 失败原因 |
|---|---|
| 1 | 「找最后一条 import」匹配到了**类内部的动态 import**，导入被插到第 3915 行 |
| 2 | 相对导入没重基（新文件在 `src/host/` 下，`./core/x` 要变 `../core/x`） |
| 3 | 只复制了**第一组** import（`host.ts` 的 import 分散在 100 多行，`truncateOutput` 在 L77） |
| 4 | 被搬的 body 内部**还夹着一条**未重基的 import → 与顶部重复声明 |
| 5 | 按模块合并 import 时把 `sessionCwdOf` 的绑定弄丢 → 运行期 `is not defined` |

**正确姿势**：

```bash
# 1) 先拆：把目标区间原样搬进新文件（导入段留空）
# 2) 让编译器报错，拿到完整缺失符号清单
cd plugin && npx tsc --noEmit 2>&1 | grep "Cannot find name"
# 3) 按清单一次性手写 import（值和类型分开：import { x } / import type { T }）
# 4) 原文件只需 import 它用到的「私有」符号（原本没 export 的那几个）
# 5) 全量：npm test && node ../tools/check-architecture.mjs
```

## 验证方式
- `npx tsc --noEmit` 无 `Cannot find name`
- `node scripts/build-lib.mjs` 退出码 0 且打印 `OK — N module(s)`
- 全量 `npm test` 绿
- `node tools/check-architecture.mjs` 的 A6 行数棘轮不超上限

## 不适用条件
- 目标文件 import 只有寥寥几行且集中在文件头（这种情况下复制 import 块是安全的）
- 语言没有静态类型检查（那时只能靠运行时测试兜底，风险更高）
- 只是**移动整个文件**（不改导入关系）——那种情况直接 `git mv` 即可
